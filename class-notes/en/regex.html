This chapter is about regular expressions (regex for short). A regular expression is a small language for writing down the shape of text, such as "three digits, a dash, four digits". Once the shape is written down, Python's re module can find it (search, findall), split text on it (split) and rewrite it (sub). We start by seeing where in and split run out of steam, learn the pattern syntax piece by piece with a small test bench, and then move on to groups and substitution, input validation and its limits, analysing a web server log, and processing Korean text. The practice programs are first_search, try_pattern, reformat, validate, log_report and hangul.

Why Regular Expressions?

Where in and split Fall Short

The string methods strip, lower, split and in are enough when you are dealing with fixed characters. But once you need to find a shape rather than fixed characters, as in "find every mobile number starting with 010", the code grows quickly. "010-" in text only tells you yes or no, and after splitting into words with split you still have to remove brackets and commas, split again on the dash, and check each piece's length and digits.

found = []
for word in text.replace("(", " ").replace(",", " ").split():
    word = word.strip(".")
    parts = word.split("-")
    if (len(parts) == 3 and parts[0] == "010"
            and len(parts[1]) == 4 and len(parts[2]) == 4
            and parts[1].isdigit() and parts[2].isdigit()):
        found.append(word)

With a regular expression the same job is one line describing the shape. \d is one digit and {4} means "four times".

import re

pattern = r"010-\d{4}-\d{4}"
print(re.findall(pattern, text))   # ['010-1234-5678', '010-9876-5432']

A regex is not always the answer. For finding fixed text or splitting on spaces, in, startswith and split are easier to read and faster. Reach for a regex when the text has a shape: numbers, dates, log lines.

Raw Strings r"..."

Regular expressions are full of backslashes: \d, \w, \b. In an ordinary string, though, Python interprets backslashes first: "\n" becomes one newline character and "\b" one backspace character. A raw string, with an r in front, leaves backslashes alone. That is why patterns are always written as r"...".

print(len("\n"), len(r"\n"))    # 1 2
print("C:\temp\new")            # \t is a tab, \n a newline: the path breaks
print(r"C:\temp\new")           # C:\temp\new

Forget the r and Python 3.14 prints SyntaxWarning: "\d" is an invalid escape sequence. It happens to work for now, but it is going to become an error. You can see the warning yourself in the third step of first_search.

Functions of the re Module

Finding: search, match, fullmatch

All three return a Match object when they match and None when they do not. They differ in where the match has to be.

import re

s = "주문 010-1234-5678"
print(re.search(r"\d+", s))            # <re.Match object; span=(3, 6), match='010'>
print(re.match(r"\d+", s))             # None: only tries at the start
print(re.fullmatch(r"\d+", "2026"))    # match: the whole string is digits
print(re.fullmatch(r"\d+", "2026년"))  # None

On a Match object, group() is the matched text, start() and end() are positions, and span() is a tuple of the two. Like a slice, end() is the position after the match.

m = re.search(r"010-\d{4}-\d{4}", text)
print(m.group(), m.start(), m.end())   # 010-1234-5678 4 17

Checking for None

Call m.group() when nothing matched and you get AttributeError: 'NoneType' object has no attribute 'group', the most common regex error of all. Check with if m: before using the result: a Match object is true and None is false.

m = re.search(r"\d+", text)
if m:
    print(m.group())
else:
    print("no number")

Finding All: findall, finditer

findall returns the matched strings as a list; finditer hands out Match objects one at a time. When you also need positions, use finditer.

text = "사과 3개, 배 12개, 귤 7개"
print(re.findall(r"\d+", text))        # ['3', '12', '7']
for m in re.finditer(r"\d+", text):
    print(m.group(), m.span())         # 3 (3, 4)  12 (9, 11)  7 (16, 17)

Character Classes

Square brackets mean "one character from this set". Inside, - writes a range, and a ^ right at the start negates the set. \d, \w and \s are shorthands for common classes; the capitals \D, \W and \S are their opposites. \w includes the underscore but not the hyphen, so kebab-case splits into two words.

$ python3 try_pattern.py '[^a-z ]' 'Hello, World 42!'
  marked [H]ello[,] [W]orld [4][2][!]
$ python3 try_pattern.py '\w+' 'snake_case, kebab-case, 한글123'
  marked [snake_case], [kebab]-[case], [한글123]

Quantifiers

A quantifier applies to the single character (or group) right before it: in colou?r the ? applies only to the u. Quantifiers are greedy by default and take as much as they can, which is why \d{3,4} takes 1234 out of 12345.

$ python3 try_pattern.py '\d{3,4}' '12 123 1234 12345'
  marked 12 [123] [1234] [1234]5

Anchors and Word Boundaries

^, $ and \b match positions, not characters. \b sits between a word character and a non-word character (or the end of the string). Use it to find "cat" without the cat inside concat or cats.

$ python3 try_pattern.py '\bcat\b' 'cat concat cats cat.'
  marked [cat] concat cats [cat].

Greedy and Non-Greedy Matching

Looking for HTML tags with <.+>: it starts at the first <, .+ runs to the end of the sentence, and then it backs up one character at a time until it finds a >. The result is the whole sentence up to the last >. Put a ? after the quantifier and it becomes non-greedy, stopping at the nearest >.

$ python3 try_pattern.py '<.+>' '<b>bold</b> and <i>it</i>'
  marked [<b>bold</b> and <i>it</i>]
$ python3 try_pattern.py '<.+?>' '<b>bold</b> and <i>it</i>'
  marked [<b>]bold[</b>] and [<i>]it[</i>]

An even more precise approach is to repeat "anything but the delimiter". <[^>]+> repeats only characters that are not >, so it never needs to back up. The \[([^\]]+)\] in the log pattern works the same way.

Or (|) and Brackets

| has the lowest precedence, so \bcat|dog\b means "\bcat or dog\b". Use brackets to group it the way you mean: \b(cat|dog)\b.

Groups and Substitution

Numbered and Named Groups

Whatever sits inside brackets can be pulled out separately. Groups are numbered 1, 2, 3 in the order of their opening brackets, and group(0) is the whole match. With many groups the numbers get confusing, so give them names with (?P<name>...) and read them with m["name"]. That is how reformat takes apart the dates and phone numbers in schedule.txt.

DATE = re.compile(r"(\d{4})-(\d{2})-(\d{2})")
PHONE = re.compile(r"(?P<head>01[0-9])-(?P<mid>\d{3,4})-(?P<last>\d{4})")

m = DATE.search(text)
print(m.groups())                  # ('2026', '03', '02')
year, month, day = m.groups()

p = PHONE.search(text)
print(p["mid"], p.group("last"))   # 1234 5678
print(p.groupdict())               # {'head': '010', 'mid': '1234', 'last': '5678'}

findall and Groups

When the pattern has groups, findall returns the groups instead of the whole match: the group's string if there is one group, tuples if there are several. To group without capturing, use (?:...).

text = "2026-03-02, 2026-04-20"
re.findall(r"\d{4}-\d{2}-\d{2}", text)          # ['2026-03-02', '2026-04-20']
re.findall(r"(\d{4})-(\d{2})-(\d{2})", text)    # [('2026', '03', '02'), ('2026', '04', '20')]
re.findall(r"(\d{4})-(?:\d{2})-(?:\d{2})", text)  # ['2026', '2026']

re.sub with Backreferences

re.sub(pattern, replacement, string) returns a new string with every match replaced. In the replacement, \1 and \2 stand for what the groups caught, and \g<name> for a named group. The replacement needs an r too: without it, "\3" becomes character code 3 and an invisible character is inserted.

print(DATE.sub(r"\3.\2.\1", "2026-03-02 개강"))   # 02.03.2026 개강

date = re.compile(r"(?P<y>\d{4})-(?P<m>\d{2})-(?P<d>\d{2})")
print(date.sub(r"\g<d>/\g<m>/\g<y>", "due 2026-06-15"))   # due 15/06/2026
print(re.subn(r"\d", "#", "PIN 4821, room 301"))  # ('PIN ####, room ###', 7)

re.sub with a Function

Pass a function as the replacement and it is called with the Match object for every match; the string it returns takes the match's place. Use this when the replacement differs from match to match. The function below prints as many * as the middle part has digits.

def mask(m):
    return m["head"] + "-" + "*" * len(m["mid"]) + "-" + m["last"]

print(PHONE.sub(mask, "담당 김민지 010-1234-5678"))   # 담당 김민지 010-****-5678

re.split and Backreferences in a Pattern

str.split knows only one separator; re.split uses a pattern as the separator. Inside a pattern, \1 means "exactly the text group 1 caught", so you can find a word written twice in a row.

re.split(r"\s*[,;/]\s*", "사과, 배;귤  /감 ,  포도")   # ['사과', '배', '귤', '감', '포도']
re.findall(r"\b(\w+) \1\b", "this is is a test test")  # ['is', 'test']

compile and Flags

re.compile parses a pattern once and keeps it as a Pattern object. The re module caches recent patterns, so the speed difference is small, but naming a reused pattern, as in PHONE or DATE, makes the code easier to read. Flags change how the pattern is interpreted and can be combined with | (re.I | re.M).

Because re.VERBOSE ignores whitespace, a real space must be written as \s or \ . The email pattern in validate uses this flag to explain itself line by line.

EMAIL = re.compile(r"""
    [\w.+-]+        # local part: letters, digits, . + -
    @
    [\w-]+          # first domain label
    (\.[\w-]+)+     # one or more .labels: .com  .co.kr
""", re.VERBOSE)

Input Validation

Check the Whole String with fullmatch

validate reads "kind value" lines and judges mobile numbers, email addresses and dates. Validation must use fullmatch: search finds a match even with anything stuck before or after it. ^...$ looks similar, but $ also matches just before a newline at the end of the string, so it lets "123\n" through.

PHONE = re.compile(r"01[016-9]-?\d{3,4}-?\d{4}")

PHONE.search("tel:010-1234-5678 (call me)")   # match: wrong for validation
PHONE.fullmatch("tel:010-1234-5678 (call me)")  # None
re.match(r"^\d+$", "123\n")                    # match!
re.fullmatch(r"\d+", "123\n")                  # None

The Limits of Regex Validation

A regex checks the shape only. The results above show its limits:

  • Dates: even a careful pattern that limits months to 01–12 and days to 01–31 accepts 2026-02-31. Putting the length of every month and leap years into a pattern would make it unreadable. So validate.py checks only the shape with a regex and lets datetime.date(year, month, day) decide whether the day exists (it raises ValueError if not).
  • Email: the standard allows so many forms of address that a complete regex is practically unusable. A practical pattern only filters out clearly broken input; the real check is sending a confirmation message. Because \w is Unicode, 홍길동@예시.한국 passes too; whether to accept it is the program's decision.
  • Phone numbers: the right shape does not mean the number is in service. With two -?, 010-12345678 (only one dash) passes as well. The more you allow, the more of these cases slip in.

Remember the rule: check the shape with a regex and the meaning with code.

f-string Alignment and Hangul

The result table lines up its columns with f"{kind:<6} {value:<26} {result}", yet the line with Korean is pushed out of line. Format specs count characters, but each Hangul character takes two columns in the terminal. A table of English letters and digits has no such problem; to align Korean text you would have to compute the display width yourself (unicodedata.east_asian_width).

A Log Analyzer

Taking One Log Line Apart

A web server writes one log line per request. The access.log of log_report has 40 lines like this:

192.168.0.12 - - [26/Nov/2026:09:18:05 +0900] "GET /static/app.js HTTP/1.1" 200 40213

Client IP, the time in square brackets, the request in quotes (method, path, protocol), status code, response size. report.py writes this shape over several lines with re.VERBOSE and names every part it needs.

LINE = re.compile(r"""
    (?P<ip>\d{1,3}(?:\.\d{1,3}){3})       # 192.168.0.12
    \s-\s-\s
    \[(?P<day>[^:\]]+):(?P<hour>\d{2}):\d{2}:\d{2}[^\]]*\]\s
    "(?P<method>[A-Z]+)\s(?P<path>\S+)\s[^"]*"\s
    (?P<status>\d{3})\s
    (?P<size>\d+|-)
""", re.VERBOSE)

An IP is "1 to 3 digits, then (a dot and 1 to 3 digits) three times": the repeated part is grouped with (?:...) and given {3}. Inside the brackets and quotes, "anything but the closing symbol" ([^\]], [^"]) avoids the greedy-matching trap.

Counting with Counter

collections.Counter is a dictionary that counts "how many times per key". += 1 on a missing key is no error; it starts from 0. most_common(n) returns the n most frequent entries. Lines that do not fit are not allowed to stop the program; only their line numbers are recorded.

paths = Counter()
bad = []
with open(filename, encoding="utf-8") as f:
    for number, line in enumerate(f, start=1):
        m = LINE.match(line)
        if not m:
            bad.append(number)
            continue
        paths[m["path"]] += 1
        ...
print(paths.most_common(3))   # [('/index.html', 10), ('/static/app.js', 7), ('/api/items', 6)]

An Aligned Report

Format specs line up the columns. :<16 left-aligns in 16 columns, :>5 right-aligns in 5, :>7.1% multiplies by 100 and prints one decimal place and a % sign, right-aligned in 7 columns, and :, adds thousands separators. Numbers on the right and names on the left make a table easy to read.

def print_top(title, counter, n, total):
    print(f"\nTop {n} {title}")
    print(f"  {'':<16} {'hits':>5} {'share':>7}")
    for key, hits in counter.most_common(n):
        print(f"  {key:<16} {hits:>5} {hits / total:>7.1%}")

MULTILINE and the Shell's grep

Read the whole file as one string and ^ matches only once, at the very start. You need re.MULTILINE for it to match at every line.

text = open("access.log", encoding="utf-8").read()
ip = r"^\d+\.\d+\.\d+\.\d+"
re.findall(ip, text)                     # ['192.168.0.12']: only the first line
len(re.findall(ip, text, re.MULTILINE))  # 39

The shell's grep speaks regular expressions too: grep -E '" [45][0-9]{2} ' access.log shows the error lines straight away. The syntax of grep -E (extended regular expressions) has no \d, though, so write [0-9]. grep is handy for a quick look; Python is better for counting and building tables.

Korean Text

The Unicode Range [가-힣]

The 11,172 precomposed Hangul syllables form one unbroken block of Unicode from U+AC00 (가) to U+D7A3 (힣), so [가-힣] alone covers every complete Hangul syllable. Single letters such as ㅋ and ㅠ (compatibility jamo) live in another block (U+3131–U+3163) and need their own class, [ㄱ-ㅎㅏ-ㅣ].

print(hex(ord("가")), hex(ord("힣")))          # 0xac00 0xd7a3
re.findall(r"[가-힣]", "한글 ㅎㅏㄴ 漢字 abc")       # ['한', '글']
re.findall(r"[ㄱ-ㅎㅏ-ㅣ]", "한글 ㅎㅏㄴ 漢字 abc")   # ['ㅎ', 'ㅏ', 'ㄴ']

hangul picks Hangul words, jamo (ㅋㅋㅋ, ㅠㅠ), English words and star ratings out of product reviews, and builds clean sentences with the symbols and jamo removed.

HANGUL_WORD = re.compile(r"[가-힣]+")
JAMO_RUN = re.compile(r"[ㄱ-ㅎㅏ-ㅣ]+")
ENGLISH = re.compile(r"[a-z]+", re.IGNORECASE)
RATING = re.compile(r"별점\s*(\d)점")

cleaned = JAMO_RUN.sub("", text)
cleaned = re.sub(r"[^가-힣A-Za-z0-9\s]", "", cleaned)   # keep Hangul, letters, digits, spaces

\w Is Unicode

In Python 3, \w, \d and \b in str patterns follow Unicode: Hangul and accented letters such as ï are word characters. If you want English letters and digits only, pass re.ASCII or spell it out as [A-Za-z0-9_].

re.findall(r"\w+", "파이썬3 최고! naïve_code")            # ['파이썬3', '최고', 'naïve_code']
re.findall(r"\w+", "파이썬3 최고! naïve_code", re.ASCII)  # ['3', 'na', 've_code']

A Limit: Particles Cannot Be Told by Shape

To count "배송이" and "배송은" as the same word, you might write a pattern that strips the particle at the end. It works for 배송이, 품질은, 포장도 and 고기를, but cuts "나이" (age) down to "나": whether a final "이" is a particle or part of the word cannot be told from the shape alone. Analysing Korean words is a job for a morphological analyser with a dictionary; regexes are for the clean-up before that (removing symbols, picking out numbers and jamo).

josa = re.compile(r"([가-힣]+?)(은|는|이|가|을|를|도)?")
for w in ["배송이", "품질은", "포장도", "고기를", "나이"]:
    print(w, "->", josa.fullmatch(w)[1])   # 배송 품질 포장 고기 나(!)

Common Mistakes

  • Leaving out the r. "\b" is a backspace character, not a word boundary. Write both patterns and replacements as r"...".
  • Not checking for None. Chaining re.search(...).group() raises AttributeError when nothing matches.
  • Validating with search or match. To check the whole input, use fullmatch.
  • Not escaping the dot. . is any character. A real full stop is \. (or [.] inside brackets).
  • Being surprised by a greedy .*. Use .*? or [^delimiter]*.
  • Forgetting that findall returns groups. To group without capturing, use (?:...).
  • Trying to do everything with a regex. Whether a date exists or an email arrives is checked with code and other means. For nested structures like HTML or JSON, use a real parser (html.parser, json).

Summary and Exercises

  • A regular expression is a language for the shape of text; the re module finds it (search, findall, finditer), checks it (fullmatch), splits on it (split) and rewrites it (sub).
  • Character classes say "which character", quantifiers "how many times", anchors "where".
  • Groups pull out parts of a match; backreferences and functions rewrite them.
  • Give frequently used patterns a name with re.compile, and comment long ones with re.VERBOSE.
