The stock MVP from Week 11, Session 2 was a command-line program: it read a CSV (storage.py), validated and analyzed it (logic.py) and wrote an HTML report to a file (report.py). These examples move the same flow into a Flask web app. Instead of writing a report file, the app reads and analyzes the data each time a browser sends a request and builds the HTML on the spot. Start with sample2_korea, the closest to the lecture, then sample1_us with a different currency and code format, and finish with sample4_sqlite, which stores the data in SQLite. All numbers are fictional class data for 2026-11-05, not live prices.

Project structure

All three projects are split into the same four parts. Each file does one job, so you can change the page or the way data is stored without touching the other files.

FileJob
app.pyReceives HTTP requests, turns errors into status codes (400, 500) and renders the template
storage.pyReads the CSV. All file I/O lives here
logic.pyValidates one row (parse_row), filters by market and sorts by change (analyze), and summarizes (summarize). Pure functions with no I/O
templates/index.htmlThe Jinja template that draws the table and the summary

sample4 has one more file, database.py, for SQLite.

Routes and query strings

@app.get('/') connects GET requests for the address / to the function index(). The chosen market arrives in the query string after the address, ?market=KOSPI, and is read with request.args.get('market', 'ALL'). Without a value it defaults to ALL.

@app.get('/')
def index():
    market = request.args.get('market', 'ALL')
    ...
    try:
        quotes = load_quotes(app.config['DATA_PATH'])
        rows = analyze(quotes, market)
        summary = summarize(rows)
    except ValueError as exc:
        error, status = str(exc), 400
    except OSError:
        error, status = '데이터 파일을 읽을 수 없습니다.', 500
    return render_template('index.html', ...), status

Note that error handling splits into two branches. When the input is wrong, such as an unknown market name or a bad CSV row, a ValueError is raised and the app answers 400 (Bad Request). When the problem is on the server side, such as an unreadable data file, it answers 500. Either way the program does not crash; it returns a page with the error message.

Calculation rules

The change is (close − previous close) / previous close × 100. The computed value is kept unrounded and shown with two decimal places only on screen. The mean is an equal-weight sample mean of the selected stocks, so it is not a market index return. A CSV with only a header is a valid empty sample and shows the mean as N/A, but a missing file is an error.

  • Korean stocks (sample2, sample4): prices are whole won and volumes whole shares. Codes such as 005930 are handled as strings to keep the leading 0. Means: ALL +0.40%, KOSPI +0.33%, KOSDAQ +0.50%.
  • US stocks (sample1): prices are stored as whole cents and converted to USD on screen (scale=100). The markets are NASDAQ/NYSE and codes are uppercase tickers. The ALL mean is +0.40%.

Jinja auto-escaping

Jinja, Flask's template engine, automatically replaces HTML special characters when it prints a value such as {{ row.name }}. So even if a stock name contains a tag like <script>, it is not executed but printed literally as &lt;script&gt;. That is why we don't write code that pastes data straight into the page ourselves.

Storing data in SQLite (sample4)

sample4 draws the page from an SQLite database instead of the CSV. Loading the data is not done by a web request but by a separate command, flask --app app init-db, registered with @app.cli.command('init-db').

flask --app app init-db
python app.py
  • Validate first: import_snapshot() validates every row before deleting the existing ones. Bad data such as a duplicate code is rejected before the database is touched.
  • One transaction: the delete and the inserts are committed together inside with connection:, so if anything fails the previous data stays.
  • Read-only connection: read_quotes() opens the file with mode=ro. When the database file is missing it fails instead of creating an empty database, and the page tells you to run init-db first.
  • After editing the CSV, import it again with init-db to see the change on the page.

database.py defines read_quotes() twice. In Python the later definition replaces the earlier one, so the one actually used is the second (mode=ro).

Running it in this web lab

On a real PC you create a virtual environment for each project, install Flask with pip install -r requirements.txt, run python app.py and open an address such as http://127.0.0.1:5002 in your browser. The virtual machine in this web lab already has Flask, but it has no network connection to the page, so your browser cannot reach its server. The example pages therefore run it like this:

  • Start the server in the background: python3 app.py > server.log 2>&1 &
  • Send requests from inside the machine with wget and find the lines you need in the HTML with grep.
  • Check status codes and error messages with app.test_client(), which sends requests to the app without a server — the usual tool for automated tests.
  • Copy the fetched HTML and static/style.css to /mnt/host and save them with Download to see the page in your own browser.
  • Stop the server with kill %1 (on a real PC, Ctrl+C).

sample3, which uses the Naver news API, needs an external network and is not included in this lab.
