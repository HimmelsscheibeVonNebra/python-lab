In this session we follow object-oriented programming (OOP) from start to finish with a single bank account. Starting from code that handles an account with only variables and functions, we build a class that bundles related data and behavior into one object, express the initial state with __init__ and self, and express state changes with methods. Then we apply the four principles of OOP, encapsulation, abstraction, inheritance and polymorphism, to the code one by one. The example files are numbered step by step (01 to 08), and in the lab you complete bank_account and the optional savings_account. All amounts in this lecture are integers in won.

The slides assume you copy the examples into Colab and run them there, but in this web lab you run them directly with python3 filename.py in the terminal of each example page.

01 · Classes and Objects

An account as variables

Every account has an owner and a balance. Each additional account needs another pair of variables. Which values belong to the same account can only be told from the variable names. Run it in 01_variables_and_functions.

minsu_owner = "Minsu"
minsu_balance = 10000
jisu_owner = "Jisu"
jisu_balance = 5000
print(minsu_owner, minsu_balance)   # Minsu 10000
print(jisu_owner, jisu_balance)     # Jisu 5000

A function needs the right data

The function receives the balance explicitly, and the caller stores the returned value again. If you pass another account's balance by mistake, the function cannot tell. An object carries its own data together with the related behavior.

def deposit(balance, amount):
    return balance + amount

minsu_balance = 10000
minsu_balance = deposit(minsu_balance, 3000)
print(minsu_balance)   # 13000

Objects have data and behavior

One object represents one account. A class defines a kind of object, and an instance is one object made from that class. An account object's data attributes are owner and balance, and its methods are deposit(amount) and withdraw(amount).

The first class

class starts a class definition, and the indented body belongs to the class. pass is an empty statement that does nothing; for now it just holds the place. Calling BankAccount() creates an instance.

class BankAccount:
    pass

account = BankAccount()
print(type(account).__name__)   # BankAccount

Attributes belong to an object

The dot selects an attribute. Assigning, as in account.owner = ..., stores data in this object, and reading account.balance gets the current value.

account = BankAccount()
account.owner = "Minsu"
account.balance = 10000
print(account.owner, account.balance)   # Minsu 10000

Two objects, separate balances

Each call to BankAccount() creates a new object. The same attribute name can hold a different value in each object, and changing Minsu's balance leaves Jisu's balance as it is. 02_classes_and_objects also shows at the end that minsu is jisu is False.

minsu = BankAccount()
minsu.balance = 10000
jisu = BankAccount()
jisu.balance = 5000
minsu.balance = minsu.balance + 3000
print(minsu.balance, jisu.balance)   # 13000 5000

Class, object and instance

A class defines one kind of object. Each account is a separate object. "Instance" is the word for the relationship between an object and its class: each account is an instance of BankAccount.

02 · Initialization and Methods

Initialization with __init__

Python calls __init__ when it creates a new instance. The arguments provide the initial values, and the attributes assigned to self stay on that instance.

class BankAccount:
    def __init__(self, owner, balance):
        self.owner = owner
        self.balance = balance

Creating initialized accounts

The arguments match owner and balance in order. Python passes the new object as self, so you do not write it in the call. Each call initializes its own instance.

minsu = BankAccount("Minsu", 10000)
jisu = BankAccount("Jisu", 5000)
print(minsu.owner, minsu.balance)   # Minsu 10000
print(jisu.owner, jisu.balance)     # Jisu 5000

self identifies the current instance

self is the conventional parameter name. self.owner is an attribute of the current object, and owner is the value passed in this call. self.owner = owner stores that value in the object. Check it in 03_init_and_self.

account = BankAccount("Minsu", 10000)
print(account.owner)   # Minsu

Class variables and instance variables

A class variable is defined in the class body outside any method, and every instance can read the shared value. An instance variable is usually defined on self in __init__, and each account has its own owner and balance. 03b_class_and_instance_variables goes on to show that when the class variable changes, every account reads the new value, and that assigning the same name on one instance creates a new attribute on that instance only.

class BankAccount:
    bank_name = "Python Bank"        # class variable

    def __init__(self, owner, balance):
        self.owner = owner           # instance variable
        self.balance = balance

minsu = BankAccount("Minsu", 10000)
jisu = BankAccount("Jisu", 5000)
print(minsu.bank_name, jisu.bank_name)   # Python Bank Python Bank
print(minsu.balance, jisu.balance)       # 10000 5000

A method changes its object's state

A method is a function defined inside a class. self selects the account whose balance changes. This first version assumes the amount is positive.

def deposit(self, amount):
    self.balance = self.balance + amount
    return True

Calling an instance method

minsu.deposit(3000) calls the method on minsu, and Python passes minsu as self. The call changes minsu.balance. Because the object before the dot becomes self, only that account's balance changes, and other instances keep their own state.

minsu = BankAccount("Minsu", 10000)
jisu = BankAccount("Jisu", 5000)
accepted = minsu.deposit(3000)
print(accepted, minsu.balance)   # True 13000
print(jisu.balance)              # 5000

Withdrawal is another method

The withdrawal method uses the same account state. For now it assumes the amount is positive and the balance is sufficient; checks for invalid requests are added in the next section.

def withdraw(self, amount):
    self.balance = self.balance - amount
    return True

return and print have different jobs

return gives a value back to the caller, and print shows a value on the screen. The method changes the balance before returning. Check it in 04_methods.

account = BankAccount("Minsu", 10000)
accepted = account.withdraw(4000)
print(accepted)          # True
print(account.balance)   # 6000

03 · Encapsulation: State and the Rules for Changing It

Direct changes can break a rule

An account's balance must not become negative. But a direct assignment can skip the withdrawal rule. We need a clear way to read and change the balance. In the second step of the 04_methods page you can see both a withdraw without checks accepting a withdrawal larger than the balance and the direct assignment below.

account = BankAccount("Minsu", 10000)
account.balance = -9999
print(account.balance)   # -9999

Encapsulation: state and rules together

Keep related data and methods in one class, and check changes through public methods. A rejected request does not change the state.

Encapsulation and the account interface

The underscore in _balance marks it as an internal attribute. get_balance() reads the current value, and deposit() and withdraw() control the valid changes.

class BankAccount:
    def __init__(self, owner, balance):
        self.owner = owner
        self._balance = balance

    def get_balance(self):
        return self._balance

A deposit can be rejected

Zero and negative numbers are invalid amounts. A rejected call returns before changing the state, and a valid call changes the balance and then returns True.

def deposit(self, amount):
    if amount <= 0:
        return False
    self._balance = self._balance + amount
    return True

A withdrawal checks two conditions

The amount must be positive and must not exceed the balance. Withdrawing the whole balance is allowed.

def withdraw(self, amount):
    if amount <= 0 or amount > self._balance:
        return False
    self._balance = self._balance - amount
    return True

Rejected operations preserve the balance

A failed call returns False and the balance stays the same. After a successful withdrawal of the full amount, 0 is left. 05_encapsulation runs the operations in the same order as the lab's table of expected results.

account = BankAccount("Jisu", 5000)
print(account.deposit(-1000))    # False
print(account.withdraw(6000))    # False
print(account.get_balance())     # 5000
print(account.withdraw(5000))    # True
print(account.get_balance())     # 0

An underscore is a convention

Python still allows access to _balance. The underscore only signals that it is internal, and people using the class should follow the public methods. Encapsulation depends on a clear interface and rules. In the second step of the 05_encapsulation page you can see account._balance = -1 actually go through.

ExpressionPurpose
account.get_balance()Read the state
account.deposit(1000)Request a valid change
account._balance = -1Bypass the agreed interface

04 · Abstraction: A Useful Interface for the Caller

Abstraction exposes the operations the caller needs and keeps the implementation details inside those operations. All the caller needs are the inputs and the result.

The caller uses the account interface

The caller requests a withdrawal, checks the result and reads the balance. It never changes _balance directly. Run it in 07_abstraction.

account = BankAccount("Minsu", 10000)
accepted = account.withdraw(4000)
print("Accepted:", accepted)               # Accepted: True
print("Balance:", account.get_balance())   # Balance: 6000

05 · Inheritance: Shared Behavior for Related Account Types

A SavingsAccount is a kind of BankAccount. It inherits the common account operations and adds bonus data and a bonus operation.

Inheritance extends an existing class

Writing the parent class in parentheses inherits deposit, withdraw and get_balance. Even with a body of just pass, the parent's methods work as they are. Next we will add a fixed bonus amount.

class SavingsAccount(BankAccount):
    pass

savings = SavingsAccount("Minsu", 10000)
print(savings.deposit(1000))    # True
print(savings.get_balance())    # 11000

super reuses the parent's initialization

The subclass takes one more argument (bonus). super().__init__(owner, balance) initializes owner and _balance, and self.bonus stores the new attribute.

class SavingsAccount(BankAccount):
    def __init__(self, owner, balance, bonus):
        super().__init__(owner, balance)
        self.bonus = bonus

A new method can reuse inherited behavior

add_bonus calls the inherited deposit, so the existing checks still apply. Each call adds the fixed bonus once. In 06_inheritance you can check the bonus, a deposit, a withdrawal and a rejected withdrawal in turn.

def add_bonus(self):
    return self.deposit(self.bonus)

06 · Polymorphism: The Same Call, Different Implementations

Both objects support account_type(), but each class provides its own implementation. The caller uses the same method name.

Overriding an inherited method

The parent provides a default label, and the child defines a method with the same name. Python picks the method that matches the class of the actual object. Only the methods are shown below; the full classes are in 08_polymorphism.

class BankAccount:
    def account_type(self):
        return "Standard"

class SavingsAccount(BankAccount):
    def account_type(self):
        return "Savings"

One loop works with both account types

Even when a list holds different account types, each call uses that object's implementation. There is no need to branch on the class name.

accounts = [BankAccount("Minsu", 10000),
            SavingsAccount("Jisu", 5000, 500)]
for account in accounts:
    print(account.owner, account.account_type(),
          account.get_balance())
# Minsu Standard 10000
# Jisu Savings 5000

Exit questions

  • Which object does self refer to? The object that was before the dot when the method was called.
  • How is encapsulation different from abstraction? Encapsulation focuses on state and the rules for changing it; abstraction focuses on the operations exposed to the caller.
  • What does SavingsAccount inherit? BankAccount's initialization and deposit, withdraw and get_balance.
  • Why can account_type() return different labels? Because each class defines the method with the same name in its own way, and Python picks the method of the actual object.
  • Does the underscore enforce privacy? No. It is only a convention.

Objects and OOP principles

Encapsulation organizes state and its rules, abstraction exposes useful operations, inheritance extends an existing type, and polymorphism lets one call use different behavior.
