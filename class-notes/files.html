프로그램이 끝나도 남아 있어야 하는 데이터는 파일에 저장합니다. 이 장에서는 파일을 다루는 세 가지 도구와, 파일을 다룰 때 반드시 함께 필요한 오류 처리를 배웁니다. 먼저 pathlib으로 경로를 만들고 폴더를 둘러보며, open()과 with로 파일을 열고 닫는 모드를 비교합니다. 그다음 파일이 없거나 내용이 잘못됐을 때 프로그램이 멈추지 않도록 try/except로 예외를 처리하고, raise와 직접 만든 예외 클래스로 오류를 알리는 방법을 익힙니다. 마지막으로 json으로 게임 저장 파일을 만들고, csv 모듈로 잘못된 줄을 건너뛰는 견고한 가져오기 프로그램을 만듭니다. 실습 예제는 paths, file_modes, exceptions, custom_errors, json_save, csv_import입니다.

경로와 pathlib

Path 객체

파일의 위치는 notes/todo.txt 같은 경로로 나타냅니다. 경로를 문자열로 다룰 수도 있지만, 표준 라이브러리의 pathlib.Path를 쓰면 경로를 잇고 쪼개고 확인하는 일이 메서드 하나로 끝납니다. 경로를 이을 때는 나눗셈 기호 /를 씁니다. 문자열에 "/"를 직접 붙이다 보면 빗금이 빠지거나 두 번 들어가기 쉬운데, / 연산자는 그런 실수를 막아 줍니다.

from pathlib import Path

p = Path("notes") / "archive" / "old.txt"
print(p)              # notes/archive/old.txt
print(p.name)         # old.txt
print(p.stem)         # old
print(p.suffix)       # .txt
print(p.parent)       # notes/archive
print(p.with_suffix(".bak"))   # notes/archive/old.bak
속성·메서드뜻notes/archive/old.txt의 경우
p.name마지막 조각(파일 이름)old.txt
p.stem확장자를 뺀 이름old
p.suffix확장자.txt
p.parent들어 있는 폴더notes/archive
p.exists()그 경로에 무언가 있는가True
p.is_file(), p.is_dir()파일인가, 폴더인가True, False
p.resolve()절대 경로/home/student/files/paths/notes/archive/old.txt

with_suffix처럼 이름을 바꾸는 메서드는 새 Path를 만들 뿐 디스크의 파일은 건드리지 않습니다. Path는 "어디"를 나타내는 값이고, 파일을 실제로 만들거나 지우는 것은 write_text, mkdir, unlink 같은 메서드입니다.

상대 경로와 현재 폴더

/로 시작하지 않는 경로는 상대 경로이고, 프로그램을 실행한 현재 폴더(Path.cwd())를 기준으로 해석됩니다. 셸에서 cd로 다른 폴더에 가서 같은 프로그램을 실행하면 Path("notes")는 다른 곳을 가리킵니다. 이 실습의 예제 페이지는 각 예제의 폴더로 cd한 뒤 명령을 실행하므로 상대 경로가 맞게 동작합니다. 홈 폴더는 Path.home()(이 가상 머신에서는 /home/student)입니다.

폴더 둘러보기: iterdir, glob, rglob

iterdir()는 폴더 바로 안의 항목을 모두 돌려주고, glob(패턴)은 이름이 패턴에 맞는 것만 돌려줍니다. *는 "아무 글자나 몇 개든"이라는 뜻이라 "*.txt"는 .txt로 끝나는 이름입니다. rglob은 하위 폴더까지 모두 뒤집니다. 돌려주는 순서는 정해져 있지 않으므로 화면에 보여 줄 때는 sorted()로 정렬합니다.

folder = Path("notes")
for p in sorted(folder.iterdir()):
    kind = "dir " if p.is_dir() else "file"
    print(kind, p.name)

for p in sorted(folder.glob("*.txt")):     # notes 바로 안의 .txt
    print(p.name)

for p in sorted(folder.rglob("*.txt")):    # 하위 폴더까지
    print(p)                               # notes/archive/old.txt ...

read_text와 write_text

짧은 텍스트 파일은 read_text()로 통째로 읽고 write_text()로 통째로 씁니다. write_text는 파일이 없으면 만들고, 있으면 내용을 모두 지우고 새로 씁니다. 줄 단위로 나누려면 splitlines()를 씁니다. 줄 끝의 \n이 없는 리스트가 나옵니다.

out = Path("notes/hello.txt")
out.write_text("안녕하세요\nHello\n", encoding="utf-8")   # 12 (글자 수)
text = out.read_text(encoding="utf-8")
print(text.splitlines())                  # ['안녕하세요', 'Hello']
print(len(out.read_bytes()))              # 22 (바이트 수)

encoding="utf-8"을 항상 쓰는 이유

디스크에는 글자가 아니라 바이트가 저장됩니다. 글자를 바이트로 바꾸는 규칙이 인코딩이고, 오늘날의 표준은 UTF-8입니다. UTF-8에서 영문자는 1바이트, 한글은 한 글자에 3바이트라서 위의 12글자는 22바이트가 됩니다. encoding을 생략하면 Python은 운영체제의 기본값을 쓰는데, 이 값이 컴퓨터마다 다릅니다(예전 한국어 Windows는 cp949). 내 컴퓨터에서 잘 읽히던 한글 파일이 다른 컴퓨터에서 UnicodeDecodeError를 내거나 깨진 글자로 보이는 이유입니다. 텍스트 파일을 열 때는 언제나 encoding="utf-8"을 적는 습관을 들입니다.

확인하고 만들기: exists와 mkdir

파일이 있는지 exists()로 먼저 확인하면 없는 파일을 읽다가 멈추는 일을 피할 수 있습니다. 폴더는 mkdir()로 만드는데, parents=True는 중간 폴더까지 한꺼번에 만들고 exist_ok=True는 이미 있어도 오류를 내지 않게 합니다. 두 옵션을 함께 쓰면 몇 번을 실행해도 안전합니다.

p = Path("notes/nope.txt")
if p.exists():
    print(p.read_text(encoding="utf-8"))
else:
    print(p, "does not exist, skipping")

Path("notes/out/2026").mkdir(parents=True, exist_ok=True)

paths 예제에서 explore.py로 notes 폴더를 둘러보고, 경로 쪼개기와 한글 파일 쓰기를 단계별로 실행해 봅니다.

open()과 with

파일 객체와 모드

read_text/write_text는 파일 전체를 한 번에 다룹니다. 조금씩 읽거나, 기존 파일 끝에 덧붙이거나, 큰 파일을 한 줄씩 처리하려면 open()으로 파일 객체를 얻습니다. 두 번째 인자인 모드가 파일을 어떻게 열지 정합니다.

모드뜻파일이 없으면파일이 있으면
"r" (기본값)읽기FileNotFoundError처음부터 읽는다
"w"쓰기새로 만든다내용을 모두 지우고 쓴다
"a"덧붙이기(append)새로 만든다끝에 이어 쓴다
"x"새 파일 만들기(exclusive)새로 만든다FileExistsError

모드 뒤에 b를 붙이면("rb", "wb") 글자 대신 바이트를 주고받는 바이너리 모드가 되며, 이때는 encoding을 쓰지 않습니다. 이미지나 압축 파일처럼 텍스트가 아닌 파일에 씁니다.

가장 조심할 모드는 "w"입니다. 파일을 여는 순간, 아직 아무것도 쓰지 않았어도 기존 내용이 사라집니다. 기록을 쌓아 가는 파일이라면 "a"를, 절대 덮어쓰면 안 되는 파일이라면 "x"를 씁니다.

with가 파일을 닫는다

연 파일은 다 쓰고 나면 닫아야 합니다. 닫기 전에는 쓴 내용이 아직 디스크에 다 저장되지 않았을 수 있고, 한 프로그램이 동시에 열 수 있는 파일 수에도 한계가 있습니다. f.close()를 직접 부를 수도 있지만, 그 사이에서 오류가 나면 close() 줄까지 가지 못합니다. with 문은 블록이 끝나는 순간 — 정상적으로 끝나든 오류로 빠져나가든 — 파일을 닫아 줍니다.

# 직접 닫기: 중간에 오류가 나면 close()가 실행되지 않는다
f = open("diary.txt", encoding="utf-8")
text = f.read()
f.close()

# with: 블록이 끝나면 항상 닫힌다
with open("diary.txt", encoding="utf-8") as f:
    text = f.read()
print(f.closed)     # True

닫힌 파일을 읽으려 하면 ValueError: I/O operation on closed file.이 납니다. 파일 작업은 with 블록 안에서 끝내고, 블록 밖에서는 읽어 둔 값(text)을 씁니다.

읽는 방법

코드결과언제
f.read()남은 내용 전체(문자열 하나)작은 파일
f.readline()한 줄(끝의 \n 포함), 끝이면 ""헤더 한 줄만 먼저 읽을 때
f.readlines()남은 줄들의 리스트줄을 여러 번 다시 볼 때
for line in f:한 번에 한 줄씩큰 파일, 대부분의 경우

파일 객체는 어디까지 읽었는지 기억합니다. readline()으로 첫 줄을 읽은 뒤의 readlines()에는 첫 줄이 없습니다. for line in f는 파일 전체를 메모리에 올리지 않고 한 줄씩 읽으므로 아주 큰 파일에도 쓸 수 있습니다. 각 줄 끝에는 \n이 붙어 있으니 비교하거나 출력하기 전에 strip()이나 rstrip()으로 떼어 냅니다.

쓰는 방법

f.write(s)는 준 문자열을 그대로 쓰고 줄바꿈을 붙여 주지 않습니다. print(..., file=f)는 화면에 출력할 때와 같은 규칙(공백으로 구분, 끝에 줄바꿈)으로 파일에 씁니다. f.writelines(리스트)는 리스트의 문자열을 이어 쓰며, 이것도 줄바꿈은 직접 넣어야 합니다.

with open("log.txt", "w", encoding="utf-8") as f:
    f.write("a")
    f.write("b\n")                      # 'ab\n'  (a와 b가 한 줄)
    print("c", "d", sep=",", file=f)    # 'c,d\n'
    f.writelines(["e\n", "f\n"])

코드 살펴보기: diary.py

file_modes 예제의 diary.py는 명령줄 인자로 받은 한 줄을 일기장 끝에 덧붙이고, 일기 전체를 줄 번호와 함께 보여 줍니다. 같은 파일을 두 번 엽니다. 처음에는 "a"로 열어 쓰고, 블록이 끝나 파일이 닫힌 뒤 다시 읽기용으로 엽니다.

entry = " ".join(sys.argv[1:]) or "(empty)"

with open("diary.txt", "a", encoding="utf-8") as f:
    f.write(entry + "\n")

with open("diary.txt", encoding="utf-8") as f:
    for number, line in enumerate(f, start=1):
        print(f"{number}: {line.rstrip()}")

sys.argv는 명령줄에 적은 단어들의 리스트입니다. python3 diary.py 두 번째 줄이면 ["diary.py", "두", "번째", "줄"]이므로 첫 항목을 뺀 나머지를 공백으로 이어 붙였습니다. 실행할 때마다 줄이 하나씩 늘어나는 것을 확인하고, 이어지는 단계에서 "w"가 그 기록을 한 번에 지우는 모습도 봅니다.

예외: 오류를 다루는 방법

예외와 Traceback

프로그램이 실행 중에 더 진행할 수 없는 상황을 만나면 Python은 예외(exception)를 일으킵니다. int("ten")은 ValueError, 없는 파일을 여는 것은 FileNotFoundError, 0으로 나누는 것은 ZeroDivisionError입니다. 아무도 예외를 처리하지 않으면 프로그램은 그 자리에서 멈추고 Traceback을 출력합니다.

Mina: 84.0
Traceback (most recent call last):
  File "/home/student/files/exceptions/report.py", line 13, in <module>
    report("Joon", [])
    ~~~~~~^^^^^^^^^^^^
  File "/home/student/files/exceptions/report.py", line 9, in report
    print(f"{name}: {average(scores):.1f}")
                     ~~~~~~~^^^^^^^^
  File "/home/student/files/exceptions/report.py", line 5, in average
    return sum(scores) / len(scores)
           ~~~~~~~~~~~~^~~~~~~~~~~~~
ZeroDivisionError: division by zero

Traceback은 아래에서 위로 읽습니다.

  1. 맨 아래 줄: 예외의 종류와 메시지입니다. 무엇이 잘못됐는지 알려 줍니다(ZeroDivisionError: division by zero).
  2. 바로 위의 File 줄: 예외가 실제로 일어난 곳입니다(average 함수의 5번 줄, len(scores)가 0).
  3. 그 위의 줄들: 거기까지 오게 된 호출 경로입니다. 13번 줄의 report("Joon", [])가 9번 줄을 거쳐 average를 불렀습니다. 빈 리스트를 넘긴 13번 줄이 고칠 곳일 수도 있습니다.

최근 Python은 각 줄 아래에 ~~~^^^ 표시로 문제가 된 부분을 짚어 주고(3.11부터), 터미널에서는 색으로도 구분합니다(3.13부터). Traceback이 출력되기 전에 실행된 print(여기서는 Mina: 84.0)는 그대로 남고, 예외가 난 뒤의 코드(Sora의 보고)는 실행되지 않습니다.

try와 except

예외가 날 수 있는 코드를 try 블록에 넣고, 그 예외를 만났을 때 할 일을 except 블록에 씁니다. try 안에서 예외가 나면 나머지 줄은 건너뛰고 맞는 except로 이동하며, 처리가 끝나면 try 문 다음부터 계속 실행됩니다.

text = "ten"
try:
    n = int(text)
    print("got", n)          # 예외가 나면 실행되지 않는다
except ValueError as e:
    print("not a number:", e)
print("program goes on")

as e는 예외 객체를 변수에 받습니다. 출력하면 메시지가 나오고, 종류에 따라 추가 정보도 들어 있습니다. FileNotFoundError의 e.filename, KeyError의 빠진 키 같은 것입니다.

자주 만나는 예외

예외언제 나는가예
ValueError자료형은 맞지만 값이 잘못됨int("ten"), a, b = "9".split()
TypeError자료형이 맞지 않음"3" + 4, json.dumps({1, 2})
KeyError딕셔너리에 없는 키prices["mango"]
IndexError리스트 범위 밖의 위치[1, 2][5]
ZeroDivisionError0으로 나누기7 / 0
FileNotFoundError없는 파일 열기open("nope.txt")
FileExistsError있는 파일을 "x"로 열기open("diary.txt", "x")
json.JSONDecodeErrorJSON 문법 오류json.loads("{'a': 1}")

필요한 예외만 잡는다

한 try에 except를 여러 개 둘 수 있고, 위에서부터 처음 맞는 하나만 실행됩니다. 같은 처리를 할 예외는 튜플로 묶습니다: except (ValueError, ZeroDivisionError):. 종류를 적지 않은 except:나 except Exception:은 모든 오류를 삼켜 버려서, 오타로 생긴 NameError까지 조용히 숨깁니다. 예상한 예외만 이름으로 잡고, 예상하지 못한 오류는 Traceback으로 드러나게 두는 것이 원칙입니다.

else와 finally

else 블록은 try에서 예외가 나지 않았을 때만 실행됩니다. 성공했을 때의 코드를 try 밖의 else에 두면, try에는 정말 실패할 수 있는 줄만 남아 어떤 줄의 오류를 잡으려는 것인지 분명해집니다. finally 블록은 성공하든 실패하든, 심지어 return으로 함수를 빠져나가는 중에도 마지막에 반드시 실행됩니다. 정리 작업을 둡니다.

def to_int(text):
    try:
        n = int(text)
    except ValueError:
        print("except")
        return None
    else:
        print("else")
        return n
    finally:
        print("finally")

to_int("42")    # else, finally
to_int("abc")   # except, finally
상황실행 순서
예외 없음try 전체 → else → finally
잡은 예외try(예외 난 곳까지) → 맞는 except → finally
잡지 않은 예외try(예외 난 곳까지) → finally → 바깥으로 전달(Traceback)

with open(...)이 파일을 닫는 것도 사실 이 finally와 같은 원리입니다.

코드 살펴보기: calc.py

exceptions 예제의 calc.py는 입력 한 줄마다 두 수를 나눕니다. 입력도 파일처럼 for line in sys.stdin으로 한 줄씩 읽습니다. 핵심은 try가 반복문 안에 있다는 점입니다. 그래서 한 줄이 실패해도 그 줄만 건너뛰고 다음 줄로 갑니다. try를 반복문 바깥에 두면 첫 실패에서 반복 전체가 끝납니다.

for number, line in enumerate(sys.stdin, start=1):
    try:
        a_text, b_text = line.split()   # ValueError: 두 조각이 아님
        a = int(a_text)                 # ValueError: 정수가 아님
        b = int(b_text)
        result = a / b                  # ZeroDivisionError
    except ValueError as e:
        print(f"line {number}: skipped, {e}")
    except ZeroDivisionError:
        print(f"line {number}: skipped, cannot divide by zero")
    else:
        print(f"line {number}: {a} / {b} = {result:g}")

printf '10 4\n7 0\nten 2\n9\n8 2\n'을 넣으면 성공 두 줄, 건너뛴 줄 세 개가 나옵니다. 숫자가 하나뿐인 9는 풀기(unpacking)에서 ValueError: not enough values to unpack이 나는데, int("ten")과 같은 종류라서 같은 except가 처리합니다.

확인 먼저, 아니면 시도 먼저

없는 파일에 대비하는 방법은 두 가지입니다. if p.exists():로 먼저 확인하거나(Look Before You Leap), 일단 open()하고 FileNotFoundError를 잡습니다(Easier to Ask Forgiveness than Permission). Python에서는 뒤의 방식을 흔히 씁니다. 확인과 사용 사이에 다른 프로그램이 파일을 지울 수도 있고, 권한 없음이나 깨진 내용처럼 미리 확인하기 어려운 실패도 같은 모양으로 처리할 수 있기 때문입니다. 딕셔너리에서는 prices.get("mango", 0)처럼 기본값을 주는 메서드가 더 간단할 때도 많습니다.

예외를 일으키기: raise와 사용자 정의 예외

raise

내가 만든 함수가 받은 값을 처리할 수 없을 때는 이상한 값을 돌려주지 말고 raise로 예외를 일으킵니다. 그러면 호출한 쪽이 오류를 무시하고 넘어갈 수 없고, 처리할지 말지를 그쪽에서 결정합니다. 잘못된 값에는 보통 ValueError를 씁니다.

def withdraw(self, amount):
    if amount <= 0:
        raise ValueError(f"amount must be positive, got {amount}")
    ...

except 블록 안에서 이름 없이 raise만 쓰면 방금 잡은 예외를 그대로 다시 던집니다. 로그만 남기고 처리는 위쪽에 맡길 때 씁니다.

나만의 예외 클래스

예외도 클래스입니다. Exception을 상속하면 새 예외를 만들 수 있습니다. 모듈마다 부모 예외 하나(BankError)를 두고 구체적인 예외를 그 아래 두면, 쓰는 쪽은 except InsufficientFunds로 자세히 잡을 수도, except BankError로 모듈의 오류를 한꺼번에 잡을 수도 있습니다. __init__에서 값을 속성으로 저장해 두면 잡은 쪽이 메시지 문자열을 해석하지 않고도 정보를 꺼내 쓸 수 있습니다.

class BankError(Exception):
    """Base class for every error this module raises."""

class InsufficientFunds(BankError):
    def __init__(self, balance, amount):
        super().__init__(f"balance {balance}, tried to withdraw {amount}")
        self.balance = balance
        self.amount = amount
try:
    left = account.withdraw(20000)
except InsufficientFunds as e:
    print("short by", e.amount - e.balance)    # 13000

예외는 계층을 이룹니다. except는 적힌 클래스와 그 모든 하위 클래스를 잡습니다. FileNotFoundError와 FileExistsError는 OSError의 하위 클래스이고, json.JSONDecodeError는 ValueError의 하위 클래스입니다. 그래서 여러 except를 쓸 때는 구체적인 것을 위에, 넓은 것을 아래에 둡니다. 넓은 것이 위에 있으면 아래 줄까지 내려가지 못합니다.

예외 연결: raise ... from

custom_errors 예제의 config.py는 설정 파일에서 포트 번호를 읽습니다. 실패하는 이유는 파일 없음(FileNotFoundError), 숫자 아님(ValueError), 범위 밖 등 여러 가지인데, 부르는 쪽에서 그 모두를 알 필요는 없습니다. 그래서 낮은 수준의 예외를 잡아 ConfigError 하나로 바꿔 던집니다. 이때 from e를 붙이면 원래 예외가 새 예외의 __cause__에 연결됩니다.

def read_port(path):
    try:
        with open(path, encoding="utf-8") as f:
            text = f.read().strip()
        port = int(text)
    except FileNotFoundError as e:
        raise ConfigError(f"{path}: file not found") from e
    except ValueError as e:
        raise ConfigError(f"{path}: port must be a number, got {text!r}") from e
    if not 1 <= port <= 65535:
        raise ConfigError(f"{path}: port {port} is outside 1-65535")
    return port

이 ConfigError를 아무도 잡지 않으면 Traceback이 두 개 나옵니다. 위쪽이 원인(ValueError), 그 아래에 The above exception was the direct cause of the following exception:, 맨 아래가 최종 오류(ConfigError)입니다. 원인을 감추지 않으므로 디버깅할 때 처음 무엇이 잘못됐는지 알 수 있습니다. 원인을 보여 줄 필요가 없을 때는 raise ... from None으로 연결을 끊습니다(csv_import의 BadRow가 그렇게 합니다).

JSON: 데이터를 글자로 저장하기

JSON이란

JSON(JavaScript Object Notation)은 딕셔너리와 리스트 같은 구조를 텍스트로 적는 형식입니다. 사람이 읽을 수 있고, 거의 모든 언어와 웹 서비스가 주고받을 수 있어서 설정 파일, 저장 파일, 웹 API의 응답에 널리 쓰입니다. 겉모습은 Python의 딕셔너리와 비슷하지만 규칙이 더 엄격합니다. 문자열은 반드시 큰따옴표로 쓰고, 객체의 키는 문자열이어야 하며, 마지막 항목 뒤에 쉼표를 둘 수 없습니다.

list, tuple배열 [ ]list
str문자열 "..."str

set, date, 객체저장 불가(TypeError)리스트나 문자열로 바꿔 저장

튜플은 리스트가 되고 숫자 키 1은 문자열 "1"이 되므로, 저장했다 다시 읽은 값이 원래 값과 똑같지 않을 수 있습니다. 날짜는 date.isoformat()으로 "2026-03-02" 같은 문자열로 바꿔 저장하고, 읽을 때 date.fromisoformat()으로 되돌립니다.

이름 끝의 s는 string(문자열)입니다. s가 없는 쪽은 파일 객체를 받습니다. 쓰기용 옵션 두 개를 기억합니다. ensure_ascii=False는 한글을 그대로 저장합니다(빼면 "민지"처럼 이스케이프됩니다. 틀린 것은 아니지만 사람이 읽기 어렵습니다). indent=2는 줄을 바꾸고 들여 써서 사람이 읽기 좋게 만듭니다.

import json
data = {"name": "민지", "tags": ("a", "b"), "pet": None, "ok": True}
print(json.dumps(data, ensure_ascii=False))
# {"name": "민지", "tags": ["a", "b"], "pet": null, "ok": true}

코드 살펴보기: save.py

json_save 예제의 save.py는 게임 기록을 save.json에 저장합니다. 실행할 때마다 읽고, 고치고, 다시 씁니다. 읽기 함수가 두 가지 실패를 모두 처리하는 것이 핵심입니다. 처음 실행하면 파일이 없고(FileNotFoundError), 저장 도중 전원이 꺼지면 파일이 반쯤만 쓰여 있을 수 있습니다(JSONDecodeError). 어느 경우든 새 게임으로 시작합니다.

def load():
    try:
        with open(SAVE, encoding="utf-8") as f:
            return json.load(f)
    except FileNotFoundError:
        print("no save file yet: new game")
    except json.JSONDecodeError as e:
        print(f"{SAVE} is broken ({e.msg}, line {e.lineno} column {e.colno}): new game")
    return new_game()

def save(data):
    with open(SAVE, "w", encoding="utf-8") as f:
        json.dump(data, f, ensure_ascii=False, indent=2)

기본값은 상수 딕셔너리 대신 new_game() 함수가 매번 새로 만들어 돌려줍니다. 상수를 그대로 돌려주면 그 안의 history 리스트를 여러 곳이 함께 쓰게 되어, 한 곳에서 추가한 점수가 다른 곳에도 나타나는 문제가 생길 수 있습니다. JSONDecodeError는 어디가 깨졌는지 lineno와 colno로 알려 주므로, 사용자에게 그대로 보여 주면 파일을 손으로 고칠 때 도움이 됩니다.

저장된 save.json은 이렇게 생겼습니다. 메모장으로 열어 고칠 수 있다는 것이 JSON 저장 파일의 장점입니다.

CSV: 견고한 가져오기 프로그램

split(",") 대신 csv 모듈

CSV 한 줄을 strip().split(",")으로 직접 나눌 수도 있지만, 값 안에 쉼표가 들어 있으면 깨집니다. CSV는 그런 값을 "Kim, Jiwoo"처럼 큰따옴표로 감싸는데, split은 따옴표를 모르기 때문입니다. 표준 라이브러리의 csv 모듈은 따옴표와 줄바꿈 규칙을 알고 있습니다.

'"Kim, Jiwoo",math,88'.split(",")
# ['"Kim', ' Jiwoo"', 'math', '88']     네 조각으로 깨진다

DictReader와 DictWriter

csv.DictReader는 첫 줄(헤더)을 키로 써서 나머지 줄마다 딕셔너리 하나를 줍니다. row[2] 대신 row["score"]로 읽으니 열 순서가 바뀌어도 코드가 그대로 동작합니다. 값은 모두 문자열이므로 숫자는 int()로 바꿔야 합니다. 줄의 칸 수가 헤더와 다르면 이렇게 들어옵니다.

  • 칸이 모자라면: 빠진 키의 값이 None입니다({'name': '지우', 'subject': 'math', 'score': None}).
  • 칸이 남으면: 남은 값들이 None 키 아래 리스트로 들어갑니다({..., None: ['extra']}).
  • 칸은 있지만 비어 있으면: 빈 문자열 ''입니다.

csv.DictWriter는 반대로 딕셔너리를 줄로 씁니다. 열 순서를 fieldnames로 정하고, writeheader()로 헤더를, writerows()로 행들을 씁니다. 쉼표가 들어 있는 값은 자동으로 따옴표로 감쌉니다. CSV 파일은 읽을 때도 쓸 때도 newline=""으로 엽니다. 줄바꿈 처리를 csv 모듈에 맡기라는 뜻으로, 생략하면 운영체제에 따라 빈 줄이 끼거나 따옴표 안의 줄바꿈이 깨질 수 있습니다.

코드 살펴보기: importer.py

실제 데이터에는 거의 항상 잘못된 줄이 섞여 있습니다. 한 줄이 잘못됐다고 전체 가져오기를 포기하면 안 되고, 조용히 버려서도 안 됩니다. csv_import 예제의 importer.py는 좋은 줄은 모으고 나쁜 줄은 줄 번호와 이유를 보고합니다. 일을 둘로 나눴습니다. parse(row)는 한 줄을 검사해 깨끗한 딕셔너리를 돌려주거나 BadRow를 raise하고, main은 줄마다 parse를 부르며 BadRow를 잡습니다.

class BadRow(Exception):
    """A row we cannot use; the message says why."""

def parse(row):
    if None in row:
        raise BadRow(f"extra fields {row[None]}")
    if row["score"] is None:
        raise BadRow("missing score column")
    name = row["name"].strip()
    if not name:
        raise BadRow("empty name")
    try:
        score = int(row["score"])
    except ValueError:
        raise BadRow(f"score is not a whole number: {row['score']!r}") from None
    if not 0 <= score <= 100:
        raise BadRow(f"score {score} is outside 0-100")
    return {"name": name, "subject": row["subject"], "score": score}

검사하는 이유가 모두 달라도 parse는 BadRow 한 가지로 알리므로 main의 except는 하나면 됩니다. int()의 ValueError도 BadRow로 바꿔 던지는데, 원인이 메시지에 이미 다 들어 있으므로 from None으로 연결을 끊었습니다.

try:
    with open(path, encoding="utf-8", newline="") as f:
        reader = csv.DictReader(f)
        for row in reader:
            try:
                good.append(parse(row))
            except BadRow as e:
                bad += 1
                print(f"line {reader.line_num}: skipped, {e}")
except FileNotFoundError:
    print(f"error: {path} not found")
    return 1

try가 두 겹입니다. 안쪽 try는 반복문 안에 있어 한 줄의 실패를 처리하고, 바깥 try는 파일 자체가 없는 경우를 처리합니다. reader.line_num은 지금까지 읽은 파일의 줄 번호(헤더가 1)라서 cat -n scores.csv의 번호와 같습니다. 파일이 없으면 main이 1을 돌려주고 sys.exit(main(...))가 그것을 종료 코드로 씁니다. 0은 성공, 0이 아니면 실패라는 셸의 약속을 지키는 것입니다.

line 5: skipped, score is not a whole number: ''
line 6: skipped, score is not a whole number: 'eighty'
line 7: skipped, score 105 is outside 0-100
line 8: skipped, missing score column
line 9: skipped, empty name
line 10: skipped, extra fields ['extra']
4 rows saved to clean.csv, 6 skipped
average of the good rows: 82.2

흔한 실수

  • 있는 파일을 "w"로 연다. 여는 순간 내용이 사라집니다. 덧붙이려면 "a", 덮어쓰면 안 되면 "x"입니다.
  • encoding을 생략한다. 내 컴퓨터에서는 되던 한글 파일이 다른 컴퓨터에서 깨집니다. 텍스트 파일에는 항상 encoding="utf-8"을 씁니다.
  • 줄 끝의 \n을 잊는다. for line in f의 line은 \n으로 끝납니다. line == "5000"은 거짓이므로 strip()한 뒤 비교합니다. 반대로 write()는 \n을 붙여 주지 않습니다.
  • with 블록 밖에서 파일을 읽는다. 이미 닫혀 있어 ValueError: I/O operation on closed file.이 납니다.
  • except:로 모든 예외를 잡는다. 오타(NameError)나 Ctrl+C까지 삼켜 버그가 숨습니다. 예상한 예외만 이름으로 잡습니다.
  • try에 너무 많은 코드를 넣는다. 어느 줄의 오류를 잡으려는 것인지 흐려지고, 예상하지 못한 줄의 같은 종류 오류까지 잡힙니다. 성공했을 때의 코드는 else로 옮깁니다.
  • 예외를 잡고 아무것도 하지 않는다(except ValueError: pass). 데이터가 조용히 사라집니다. 건너뛰더라도 무엇을 왜 건너뛰었는지 알립니다.
  • JSON에 작은따옴표나 끝 쉼표를 쓴다. {'a': 1}과 [1, 2,]는 JSON이 아닙니다. 손으로 쓰지 말고 json.dump로 만듭니다.
  • CSV 값이 문자열이라는 것을 잊는다. row["score"] > 90은 TypeError입니다. int()로 바꾸고, 바꾸다 실패하는 경우를 처리합니다.

확인 퀴즈

  1. Path("data") / "2026" / "a.csv"의 suffix와 parent는? .csv와 data/2026입니다.
  2. 기존 로그 파일 끝에 한 줄을 더하려면 어떤 모드로 여는가? "a"입니다.
  3. with 블록 안에서 예외가 나면 파일은? 블록을 빠져나가면서 닫힙니다.
  4. else 블록은 언제 실행되는가? try에서 예외가 나지 않았을 때만 실행됩니다.
  5. finally는 return이 있어도 실행되는가? 네, 함수가 끝나기 직전에 실행됩니다.
  6. except BankError는 InsufficientFunds를 잡는가? 네, 하위 클래스이기 때문입니다.
  7. raise ConfigError(...) from e에서 e는 어디에 남는가? 새 예외의 __cause__에 남고, Traceback에도 함께 나옵니다.
  8. json.dumps((1, 2))를 loads로 되돌리면? 튜플이 아니라 리스트 [1, 2]입니다.
  9. DictReader에서 칸이 모자란 줄의 빠진 값은? None입니다.

정리

경로는 Path로 만들고 /로 잇습니다. 파일은 with open(..., encoding="utf-8")으로 열어 블록 안에서 끝내고, 모드(r, w, a, x)를 목적에 맞게 고릅니다. 실패할 수 있는 일은 try에 넣고 예상한 예외만 이름으로 잡으며, 내 함수가 처리할 수 없는 값은 raise로 알립니다. 구조가 있는 데이터는 json으로, 표 형태의 데이터는 csv로 저장하되, 읽을 때는 파일이 없거나 깨졌을 가능성을 항상 생각합니다. 각 예제 페이지에서 단계를 실행해 보고, 일부러 입력을 망가뜨려 프로그램이 어떻게 반응하는지 확인해 봅니다.
