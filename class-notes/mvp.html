이번 시간에는 하나의 프로젝트를 사용자의 문제에서 출발해 검사를 통과한 웹 보고서까지 따라갑니다. 주제는 한국 증권시장 분석입니다. 수업용 가상 CSV에 담긴 다섯 종목의 전일 종가와 당일 종가로 일간 등락률을 계산하고, 시장별로 비교해 HTML 보고서로 만듭니다. 수업은 네 막으로 진행됩니다. 요구사항과 기능으로 할 일을 정하고(ACT 1), 함수 계약과 테스트로 약속을 추적하고 증명하고(ACT 2), UML로 구조를 그리고(ACT 3), MVP를 만들어 웹 보고서를 엽니다(ACT 4). 완성본은 korea_market_mvp이고, 마지막에 동작을 바꾸지 않는 리팩터링을 tidy_lab으로 연습합니다.

개발 흐름

문서 두 개가 출발점입니다. 시나리오 문서 team-name_user-scenario.md와 명세 워크북 team-name_spec.xlsx입니다. 워크북에는 Requirement·Feature·Function·Test 시트가 있습니다. 이 둘을 이용해 SC → REQ → FEAT → FUNC → TEST를 연결한 뒤 MVP를 만듭니다. 테스트를 실행하고 페이지를 검토하며, 검사가 실패하면 고칩니다. 시나리오 문서와 프로젝트 전체 명세(project-spec.md)는 실습 페이지의 파일 목록에서 읽을 수 있습니다. xlsx 워크북은 실제 PC의 스프레드시트 프로그램으로 엽니다.

시나리오: 민지가 시장을 살펴본다

장이 마감된 뒤 민지는 몇 종목을 비교하고 싶습니다.

  • SC-01: CSV를 준비하고 보고서를 만들어 시장을 비교한다. ALL로 보고서를 만든 다음 KOSPI로 다시 만든다. 기준일, 일간 등락률 순위, 표본 요약을 확인한다.
  • SC-02: 잘못된 입력을 거절한다.
  • SC-03: 유효한 빈 보고서를 만든다.

범위와 데이터의 정직성

스냅숏 표본은 그 한계가 드러나 있을 때 쓸모가 있습니다. 제공된 가격과 거래량은 모두 수업용 가상 데이터입니다. 날짜 하나, 시장 라벨 둘, 예시 종목 다섯입니다. 평균(Mean)은 선택된 표본의 등락률을 같은 가중치로 평균한 값입니다. KOSPI/KOSDAQ 지수 수익률도 아니고 실시간 시세도 아닙니다.

입력 계약

반복문을 쓰기 전에 데이터를 먼저 정의합니다.

date,code,name,market,previous_close,close,volume
2026-11-05,005930,삼성전자,KOSPI,70000,71400,1000000
  • UTF-8 CSV이며 BOM이 있어도 받아들입니다. 헤더는 순서까지 정확해야 합니다.
  • 여섯 자리 종목 코드는 텍스트로 둡니다. 005930은 앞자리 0을 유지해야 합니다.
  • previous_close는 전 거래일 종가(원), close는 스냅숏 종가(원)이며 양의 정수입니다. volume은 거래된 주식 수로 0 이상의 정수입니다.
  • 날짜는 하나, 코드는 중복이 없어야 합니다. 두 종가는 같은 가격 기준을 씁니다.

ACT 1 · 요구사항과 기능

요구사항: 관찰 가능한 조건

요구사항 시트의 각 REQ는 SC ID와 연결되고 검사를 가집니다.

  • REQ-01: 유효한 CSV를 읽고 종목 코드를 보존한다.
  • REQ-02: 잘못된 값, 중복 코드, 섞인 날짜를 거절한다.
  • REQ-03: 일간 등락률을 계산하고, 필터하고, 정렬한다. 예: previous_close=70000, close=71400이면 +2%. KOSPI를 고르면 KOSPI 행만 나온다. 순서는 등락률 내림차순, 같으면 코드 오름차순.
  • REQ-04: 상승·하락·보합을 세고 표본 평균을 계산한다.
  • REQ-05: HTML에 날짜, 시장, 출처, 단위, 요약, 표를 보여 준다.
  • REQ-06: 파일·데이터 오류를 알리고, 실패하면 기존 HTML을 보존한다.

출력과 실패 정책도 제품의 일부입니다. 헤더만 있는 CSV는 유효한 빈 보고서(개수 0, 평균 N/A)를 만듭니다. CSV 파일이 없으면 성공한 빈 보고서가 아니라 오류입니다.

MVP 범위: Must, Should, Could

CSV → 분석 → HTML의 완전한 경로를 먼저 내놓습니다.

  • Must: 검증된 입력, 분석, 정적 HTML, 명확한 오류 처리.
  • Should: 브라우저에서 클릭하는 시장 필터.
  • Could: API 데이터, 기간 기록, 이동평균, 차트, 게시(publishing).

기존 수락 검사가 통과하기 전에는 새 Must를 추가하지 않습니다.

기능: 사용자의 세 가지 목표

python3 main.py --input data/prices.csv
python3 main.py --market KOSPI
python3 main.py --output docs/index.html
  • FEAT-01: 검증된 스냅숏을 불러온다(REQ-01/02/06).
  • FEAT-02: 시장별로 종목을 비교한다(REQ-02/03/04).
  • FEAT-03: 웹 보고서를 만들고 본다(REQ-05/06).

워크북의 Feature 시트에서 FEAT ID를 관련 요구사항 ID와 연결합니다.

기능 명세: 시장 비교

구현하기 전에 정상, 빈 입력, 오류의 결과를 씁니다.

FEAT-02 / basic
serves: REQ-02, REQ-03, REQ-04
ALL:    5 stocks, up 2 / down 2 / flat 1
        sample mean +0.40%
KOSPI:  3 stocks, sample mean +0.33%
KOSDAQ: 2 stocks, sample mean +0.50%

사용법은 python3 main.py --market KOSPI, 흐름은 스냅숏 검증 → 필터 → 계산 → 정렬 → 요약입니다. KOSPI 결과는 3종목(005930, 035420, 000660), 평균 +0.33%입니다. 고른 시장에 종목이 없으면 0종목과 N/A, 모르는 시장 이름은 CLI 오류입니다.

ACT 2 · 함수와 테스트

본문보다 계약 먼저

모듈 경계를 넘나드는 값과 실패 규칙을 일관되게 유지합니다.

Quote = {date, code, name, market,
         previous_close: int, close: int,
         volume: int}
Analyzed row = Quote + {change_pct: float}
Summary = {count, up, down, flat, mean}
  • FUNC-01 parse_row(row): 문자열 → 자료형이 있는 quote. 잘못된 필드는 ValueError.
  • FUNC-02 load_quotes(path): CSV → 목록. 파일이 없으면 OSError.
  • FUNC-04 analyze(quotes, market): 검증된 목록 → 새로 만든 정렬된 행.
  • FUNC-05 summarize(rows): 개수와 평균. 비어 있으면 평균은 None.

가장 작은 규칙 구현하기

계산은 전체 정밀도로 하고, 반올림은 보고서에서만 합니다. 공식은 (close − previous_close) / previous_close × 100입니다. 나누기 전에 0이나 음수 가격을 거절합니다. 상승, 하락, 보합은 각각 별도의 검사입니다.

def change_pct(previous_close, close):
    if previous_close <= 0 or close <= 0:
        raise ValueError("prices must be positive")
    difference = close - previous_close
    return difference / previous_close * 100

assert change_pct(70000, 71400) == 2.0
assert change_pct(200000, 198000) == -1.0
assert change_pct(100, 100) == 0.0
print("Daily change checks passed.")

모듈: 입출력은 가장자리에

모듈 다이어그램은 각 책임이 어디에 있는지 알려 줍니다.

  • main: 인자, 전체 조율, 메시지와 종료 코드.
  • storage: CSV 읽기와 원자적(atomic) HTML 쓰기. parse_row를 import합니다.
  • logic: 검증과 분석. report: escape된 HTML 문자열.

logic과 report는 파일을 열지도 사용자에게 묻지도 않습니다.

테스트: 약속마다 증거를

계속 바뀌는 온라인 가격이 아니라 고정된 예제를 씁니다.

cd ~/project/mvp/examples/korea_market_mvp
python3 -m unittest -v
  • TEST-01/12: CSV 스키마, BOM, 빈 파일, 앞자리 0 코드.
  • TEST-02/04: 정확한 등락률, 시장 필터, 동률 처리.
  • TEST-03/07: 잘못된 필드, 중복 코드, 섞인 날짜.
  • TEST-05/06: 표본 요약, 빈 선택과 N/A.

이 실습에서 폴더는 ~/project/mvp/examples/korea_market_mvp입니다. korea_market_mvp의 첫 단계가 이 명령이며 12개가 모두 ok로 나옵니다.

웹과 실패 경계 테스트

계산이 맞는 것은 동작하는 보고서의 일부일 뿐입니다.

  • TEST-08: 종목 이름에 script 태그가 들어 있으면 escape한다.
  • TEST-09: CSV가 없거나 헤더가 잘못되면 기존 HTML이 바뀌지 않는다.
  • TEST-10: 출력 교체가 실패하는 상황을 흉내 내도 파일이 보존된다.
  • TEST-11: main이 기대한 KOSPI HTML을 만든다.

워크북 Test 시트에는 TEST-01~12가 자동 테스트로 PASS, TEST-13(브라우저 육안 확인)은 직접 확인하기 전까지 Not run으로 적습니다. 실제 결과(Actual)는 기대 결과(Expected)와 따로 기록합니다. 파일 테스트는 TemporaryDirectory를 쓰고, 테스트가 수업용 데모 보고서를 덮어쓰지 않게 합니다.

ACT 3 · UML

행위자, 목표, 호출 순서

읽는 사람의 질문에 답하는 다이어그램을 고릅니다.

  • 유스케이스: 학생 → 스냅숏 불러오기, 종목 비교, 보고서 보기.
  • 컴포넌트: 어느 모듈이 어느 모듈에 의존하는가.
  • 시퀀스: 성공한 한 번의 실행 동안 일어나는 호출.
  • 활동: 정상 경로와 오류 시 멈추는 분기.

시퀀스: 성공한 한 번의 실행

모든 호출 이름은 함수 계약 표에 있습니다. main → load_quotes → 각 행에 parse_row. main → analyze → summarize → render_html. main → write_html. 성공은 교체가 끝난 뒤에만 보고합니다. 브라우저는 파이썬이 끝난 뒤 생성된 파일을 엽니다.

활동: 출력을 교체하기 전에 멈추기

먼저 검증하고, 다음에 렌더링하고, 마지막에 출력 파일을 확정합니다. 잘못된 입력은 이유와 종료 코드 1로 끝납니다. 완성된 새 파일이 한 번에 옛 파일을 교체합니다. 유효한 빈 입력은 성공한 보고서 경로를 따릅니다. 전체 Mermaid 다이어그램은 project-spec.md에 있습니다.

요구사항 하나를 끝까지 추적하기

같은 ID가 통과하는 검사까지 살아남아야 합니다.

REQ-06 -> FEAT-01 / FEAT-03
       -> load_quotes / write_html / main
       -> activity error branch
       -> TEST-09 / TEST-10

REQ-03(일간 등락률과 시장 순위)이라면 FEAT-02(시장별 비교), FUNC-03 change_pct와 FUNC-04 analyze(코드 계약), 시퀀스의 analyze 호출, TEST-02/04(숫자와 순서의 증명)로 이어집니다. 연습으로 옆 사람과 REQ-05를 추적해 봅니다.

ACT 4 · MVP

완전한 경로부터 프로토타입으로

가짜(fake) 함수를 쓰면 모든 규칙이 생기기 전에도 파이프라인 전체를 실행할 수 있습니다.

def load_quotes(path):
    return [{"code": "005930", "change_pct": 2.0}]

def render_html(rows):
    return "<h1>FAKE classroom report</h1>"

rows = load_quotes("data/prices.csv")
print(render_html(rows))
<h1>FAKE classroom report</h1>

알려진 quote 하나와 작은 HTML 표로 시작합니다. 계획한 이름과 반환 자료형은 지킵니다. 가짜는 한 번에 하나씩 바꿉니다. 규칙, CSV, HTML, 출력 순서로. 최종 MVP의 Must 기능 경로에는 가짜가 하나도 없어야 합니다.

CSV에서 검증된 quote로

텍스트 변환은 한 번만 하고, 코드는 문자열로 둡니다.

import csv, io
source = ("code,previous_close,close\n"
          "005930,70000,71400\n")
row = next(csv.DictReader(io.StringIO(source)))
print(row["code"], type(row["code"]).__name__)
difference = (int(row["close"])
              - int(row["previous_close"]))
print(difference)
005930 str
1400

csv.DictReader는 모든 필드를 문자열로 읽습니다. 어떤 행도 믿기 전에 헤더가 정확한지 검사합니다. parse_row가 가격과 거래량을 검증하고 변환합니다. 선택한 시장 밖의 행이라도 모든 행을 검증합니다.

필터, 정렬, 요약

계산은 HTML과 독립적으로 유지합니다. 섞인 날짜와 중복 코드는 필터하기 전에 거절합니다. 불러온 quote는 바꾸지 않고 새 dict를 반환합니다. 반올림하지 않은 등락률로 정렬하고, 값이 같으면 종목 코드로 정렬합니다. 행이 비면 평균은 None이고, 화면에서 N/A로 바꿉니다.

ALL order from the supplied fictional CSV:
247540  +3.00%
005930  +2.00%
035420  +0.00%
000660  -1.00%
035900  -2.00%
mean    +0.40% (sample, equal weight)

HTML은 결과를 보여 주는 뷰다

서식은 보여 주는 방식을 바꿀 뿐 계산을 바꾸면 안 됩니다. render_html은 문자열을 반환하고, 쓰기는 storage가 합니다. 종목 이름처럼 외부에서 온 텍스트에는 html.escape를 씁니다. 색깔뿐 아니라 부호와 숫자도 보여 줍니다. 날짜, 출처, 가상 데이터 표시, 단위를 넣습니다.

from html import escape
name = "<b>Example</b>"
change = 2.0
print(escape(name))
print(f"{change:+.2f}%")
&lt;b&gt;Example&lt;/b&gt;
+2.00%

main: 프로그램 조립

최상위 함수가 계약들을 조율합니다.

quotes = load_quotes(args.input)
rows = analyze(quotes, args.market)
summary = summarize(rows)
html = render_html(rows, summary, market, day)
write_html(args.output, html)
# Only now print Generated ...

argparse로 --input, --output, --market을 받습니다. 데이터·파일 오류는 사용자와 맞닿는 경계(main)에서 잡습니다. write_html을 부르기 전에 모든 결과를 준비합니다. 종료 코드는 성공 0, 데이터·입출력 실패 1, CLI 사용 오류 2입니다.

MVP를 실행하고 페이지 열기

패키지 설치도 네트워크 데이터도 필요 없습니다. examples/korea_market_mvp/에서 실행합니다.

python3 -m unittest -v
python3 main.py
python3 -m http.server 8000 \
  --directory docs --bind 127.0.0.1
# Open http://localhost:8000
# Ctrl+C stops the local server.

기본 보고서에는 가상 종목 다섯 행이 들어 있습니다. docs/index.html을 직접 열거나 docs를 로컬 서버로 띄워 봅니다. 서버는 저장된 HTML을 보여 줄 뿐이므로, 시장을 바꾸려면 다시 생성합니다.

이 웹 실습의 가상 머신에는 브라우저가 없으므로 http.server 대신 생성된 파일을 내려받습니다. korea_market_mvp에서 python3 main.py를 실행한 뒤 cp docs/index.html /mnt/host/report.html을 하고, 받기 칸에 /mnt/host/report.html을 입력해 받기를 누르면 내 컴퓨터의 브라우저로 보고서를 열 수 있습니다. 같은 페이지에서 --market KOSPI, 빈 CSV, 전일종가 0인 CSV, 없는 파일, 모르는 시장 이름을 차례로 실행하며 종료 코드와 보고서 보존 여부를 확인합니다.

증거와 함께 리팩터링

동작은 똑같이 두고 구조를 개선합니다. 옮기기 전과 후에 12개 검사를 모두 실행합니다. 모호한 변수 이름은 quote, rows, summary로 바꿉니다. FIELDS와 MARKETS는 한 곳에 둡니다. HTML 서식을 함수로 뽑아내되 숫자, 순서, 메시지는 그대로 둡니다.
