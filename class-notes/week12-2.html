CSV가 들어오는 경계

CSV 셀은 문자열로 들어옵니다. 열 구조와 필수 필드를 먼저 검사하고, 검증·변환한 값만 분석 함수로 넘깁니다.

종목 코드는 문자열

int("005930")  # 5930

앞자리 0은 종목 코드의 일부입니다. 계산에 쓰는 가격과 거래량만 정수로 변환합니다.

변환 성공과 유효한 값

int("-1")  # -1

변환에 성공해도 음수 거래량은 거절합니다. 가격은 0보다 커야 하고 거래량은 0 이상이어야 합니다.

공백을 정리하는지 여부도 입력 계약에 포함됩니다. MVP에서 행 규칙은 parse_row, 전체 규칙은 analyze가 맡습니다. korea_market_mvp에서 거래량 -1인 행이 parse_row에서, 필터로 빠질 행의 코드 중복이 analyze에서 거절되는 것을 확인합니다.

최소 거래량의 자료형 계약

0 이상의 int만 허용하고 bool·문자열·실수는 거절합니다. 함수를 직접 호출할 때의 값과, CLI에서 받은 문자열을 변환한 값은 구분합니다.

def validate_min_volume(value):
    if type(value) is not int or value < 0:
        raise ValueError("min_volume must be a nonnegative integer")
    return value

isinstance(True, int)는 True이므로 bool은 따로 고려해야 합니다. 여기서는 type(value) is not int로 bool까지 거절합니다.

예외를 어디서 던지고 어디서 처리하는가

계산 규칙은 계약 위반에 ValueError를 던집니다. 저장 모듈은 파일·디코딩 실패를 호출자에게 그대로 전달합니다. CLI는 예상한 실패를 사용자 메시지와 종료 코드로 바꿉니다. 예외는 의미 있는 대응을 할 수 있는 곳에서 처리하고, 예상하지 못한 코드 오류는 개발 중에 드러나게 둡니다.

실패를 빈 결과로 바꾸는 코드

try:
    quotes = load_quotes(path)
except Exception:
    quotes = []

이렇게 쓰면 파일 누락과 코드 오류가 모두 정상적인 빈 입력처럼 보입니다.

보고서를 교체하기 전과 후

모든 입력을 읽고 검증한 다음, 새 HTML 전체를 출력 폴더의 임시 파일에 씁니다. 검증과 쓰기가 끝날 때까지 기존 보고서는 그대로 둡니다. 쓰기가 끝나면 os.replace로 목적 파일을 교체하고, 교체에 실패하면 임시 파일을 정리합니다. 이 방식은 처리할 수 있는 교체 전 실패에서 기존 결과를 보호하는 것이고, 전원이 끊기는 상황의 내구성까지 보장하지는 않습니다.

단위 테스트와 통합 테스트

self.assertAlmostEqual(change_pct(100, 110), 10.0)

단위 테스트는 작은 함수 하나의 계약을 확인합니다. 실패하면 조사할 범위가 좁습니다.

확인 방법관찰할 결과
잘못된 CSV로 main 호출실패 코드, 기존 HTML 보존
보고서를 브라우저에서 열기시장·라벨·빈 상태 표시

함수 테스트와 실제 사용자 흐름을 함께 확인합니다. 이 웹 실습에서 보고서를 브라우저로 보려면 cp docs/index.html /mnt/host/report.html 후 받기로 내려받습니다.

임시 폴더로 실험 격리

from pathlib import Path
from tempfile import TemporaryDirectory

with TemporaryDirectory() as folder:
    output = Path(folder) / "index.html"
    output.write_text("OLD", encoding="utf-8")

제출할 보고서 대신 이 경로로 실패 실험을 합니다.

드문 저장 실패 재현하기

with patch("storage.os.replace", side_effect=OSError("disk")):
    write_html(output, "NEW")

테스트 대상이 참조하는 storage.os.replace를 패치합니다. CSV 파싱 실험에는 실제 임시 파일을 씁니다.
