The stock MVP from Week 11, Session 2 was a command-line program: it read a CSV (storage.py), validated and analyzed it (logic.py) and wrote an HTML report to a file (report.py). These examples move the same flow into a Flask web app. Instead of writing a report file, the app reads and analyzes the data each time a browser sends a request and builds the HTML on the spot. First learn how to start a server and send it requests with flask_hello, the smallest app with two routes; then sample2_korea, the closest to the lecture, then sample1_us with a different currency and code format, and finish with sample4_sqlite, which stores the data in SQLite. All numbers are fictional class data for 2026-11-05, not live prices.

The smallest Flask app

A Flask app is an app object made with Flask(__name__), with connections (routes) attached that say "when a request comes to this address, run this function". The string the function returns becomes the response HTML.

from flask import Flask, request
from markupsafe import escape

app = Flask(__name__)

@app.get("/")
def home():
    return "<h1>Hello, Flask!</h1><p>Try /hello?name=Mina</p>"

@app.get("/hello")
def hello():
    name = request.args.get("name", "world")
    return f"<p>Hello, {escape(name)}!</p>"
  • @app.get("/hello"): connects GET requests for the address /hello to hello().
  • request.args.get("name", "world"): reads the value from the ?name=Mina part of the address (the query string), with a default when it is missing.
  • escape(name): replaces special characters in a value the user sent before it goes into the HTML, so a tag they typed is not run.
  • For an address with no route, Flask answers 404 (Not Found).

The stock apps below have the same structure, except that they use a template file instead of building strings, and split the work across several files.

Project structure

All three projects are split into the same four parts. Each file does one job, so you can change the page or the way data is stored without touching the other files.

FileJob
app.pyReceives HTTP requests, turns errors into status codes (400, 500) and renders the template
storage.pyReads the CSV. All file I/O lives here
logic.pyValidates one row (parse_row), filters by market and sorts by change (analyze), and summarizes (summarize). Pure functions with no I/O
templates/index.htmlThe Jinja template that draws the table and the summary

sample4 has one more file, database.py, for SQLite.

Routes and query strings

@app.get('/') connects GET requests for the address / to the function index(). The chosen market arrives in the query string after the address, ?market=KOSPI, and is read with request.args.get('market', 'ALL'). Without a value it defaults to ALL.

@app.get('/')
def index():
    market = request.args.get('market', 'ALL')
    ...
    try:
        quotes = load_quotes(app.config['DATA_PATH'])
        rows = analyze(quotes, market)
        summary = summarize(rows)
    except ValueError as exc:
        error, status = str(exc), 400
    except OSError:
        error, status = '데이터 파일을 읽을 수 없습니다.', 500
    return render_template('index.html', ...), status

Note that error handling splits into two branches. When the input is wrong, such as an unknown market name or a bad CSV row, a ValueError is raised and the app answers 400 (Bad Request). When the problem is on the server side, such as an unreadable data file, it answers 500. Either way the program does not crash; it returns a page with the error message.

Calculation rules

The change is (close − previous close) / previous close × 100. The computed value is kept unrounded and shown with two decimal places only on screen. The mean is an equal-weight sample mean of the selected stocks, so it is not a market index return. A CSV with only a header is a valid empty sample and shows the mean as N/A, but a missing file is an error.

  • Korean stocks (sample2, sample4): prices are whole won and volumes whole shares. Codes such as 005930 are handled as strings to keep the leading 0. Means: ALL +0.40%, KOSPI +0.33%, KOSDAQ +0.50%.
  • US stocks (sample1): prices are stored as whole cents and converted to USD on screen (scale=100). The markets are NASDAQ/NYSE and codes are uppercase tickers. The ALL mean is +0.40%.

Jinja auto-escaping

Jinja, Flask's template engine, automatically replaces HTML special characters when it prints a value such as {{ row.name }}. So even if a stock name contains a tag like <script>, it is not executed but printed literally as &lt;script&gt;. That is why we don't write code that pastes data straight into the page ourselves.

Storing data in SQLite (sample4)

sample4 draws the page from an SQLite database instead of the CSV. Loading the data is not done by a web request but by a separate command, flask --app app init-db, registered with @app.cli.command('init-db').

flask --app app init-db
python app.py
  • Validate first: import_snapshot() validates every row before deleting the existing ones. Bad data such as a duplicate code is rejected before the database is touched.
  • One transaction: the delete and the inserts are committed together inside with connection:, so if anything fails the previous data stays.
  • Read-only connection: read_quotes() opens the file with mode=ro. When the database file is missing it fails instead of creating an empty database, and the page tells you to run init-db first.
  • After editing the CSV, import it again with init-db to see the change on the page.

database.py defines read_quotes() twice. In Python the later definition replaces the earlier one, so the one actually used is the second (mode=ro).

Running it in this web lab

On a real PC you create a virtual environment for each project, install Flask with pip install -r requirements.txt, run python app.py and open an address such as http://127.0.0.1:5002 in your browser. The virtual machine in this web lab already has Flask, but it has no network link to your browser, so your browser cannot reach its server. Instead, use the lab's helper command web. When web start starts the server, the App preview panel opens under the terminal. It plays the browser's role: click a link, or choose a market in a form and press 조회 (Search), and the request goes to the server inside the virtual machine and the answer is drawn again. You can also type an address such as /?market=KOSPI in the address box above it and press Open. When the server stops, the panel is dimmed.

The preview panel exchanges requests and answers as files through the shared folder /mnt/host/.web, so each request takes about 0.2–1 second. The app's CSS and images are put into the answer, and JavaScript on the app's pages is not run.

Commands you can use in the terminal:

CommandWhat it does
web startStarts app.py in the current directory as a server and waits until it is ready (about 10 seconds); the preview panel then opens
web show /Shows an address in the preview panel
web get /Sends a request and shows the status code and the page as text; tables are shown one row per line, split by |
web get '/?market=KOSPI'Put an address with a query string in single quotes
web html /Shows the raw HTML
web save file.htmlSaves the page, CSS included, in /mnt/host. Type its name in the box above and press Download to open it in your own browser
web logThe server log (address and status code of each request)
web stopStops the server. After editing the code, run web stop and then web start again

11주차 2차시에서 만든 주가 MVP는 CSV를 읽고(storage.py), 검증·분석하고(logic.py), HTML 보고서를 파일로 쓰는(report.py) 명령행 프로그램이었습니다. 이 예제들은 같은 흐름을 Flask 웹 앱으로 옮깁니다. 파일로 보고서를 쓰는 대신, 브라우저의 요청이 올 때마다 데이터를 읽고 분석해 그 자리에서 HTML을 만들어 돌려줍니다. 먼저 라우트 두 개짜리 가장 작은 앱 flask_hello로 서버를 띄우고 요청하는 방법을 익힌 뒤, 강의와 가장 가까운 sample2_korea, 통화와 종목 코드가 다른 sample1_us, 데이터를 SQLite에 저장하는 sample4_sqlite 순서입니다. 모든 수치는 2026-11-05 기준 가상 수업 데이터이며 실시간 시세가 아닙니다.

가장 작은 Flask 앱

Flask 앱은 Flask(__name__)로 만든 app 객체에 "이 주소로 요청이 오면 이 함수를 실행하라"는 연결(라우트)을 붙인 것입니다. 함수가 돌려준 문자열이 그대로 응답 HTML이 됩니다.

from flask import Flask, request
from markupsafe import escape

app = Flask(__name__)

@app.get("/")
def home():
    return "<h1>Hello, Flask!</h1><p>Try /hello?name=Mina</p>"

@app.get("/hello")
def hello():
    name = request.args.get("name", "world")
    return f"<p>Hello, {escape(name)}!</p>"
  • @app.get("/hello"): 주소 /hello로 오는 GET 요청을 hello()에 연결합니다.
  • request.args.get("name", "world"): 주소의 ?name=Mina 부분(쿼리 문자열)에서 값을 읽고, 없으면 기본값을 씁니다.
  • escape(name): 사용자가 보낸 값을 HTML에 넣기 전에 특수 문자를 바꿔, 입력한 태그가 실행되지 않게 합니다.
  • 연결되지 않은 주소에는 Flask가 404(Not Found)로 답합니다.

아래의 주식 앱들도 같은 구조입니다. 다만 문자열을 직접 만드는 대신 템플릿 파일을 쓰고, 일을 여러 파일로 나눕니다.

프로젝트 구조

세 프로젝트는 모두 같은 네 부분으로 나뉩니다. 각 파일이 한 가지 일만 하므로, 화면을 바꾸거나 데이터 저장 방식을 바꿀 때 다른 파일은 그대로 둘 수 있습니다.

파일하는 일

storage.pyCSV를 읽는다. 파일 입출력은 여기에만 있다

라우트와 쿼리 문자열

@app.get('/')는 주소 /로 오는 GET 요청을 index() 함수에 연결합니다. 시장 선택은 주소 뒤의 쿼리 문자열 ?market=KOSPI로 전달되고, request.args.get('market', 'ALL')로 읽습니다. 값이 없으면 기본값 ALL입니다.

@app.get('/')
def index():
    market = request.args.get('market', 'ALL')
    ...
    try:
        quotes = load_quotes(app.config['DATA_PATH'])
        rows = analyze(quotes, market)
        summary = summarize(rows)
    except ValueError as exc:
        error, status = str(exc), 400
    except OSError:
        error, status = '데이터 파일을 읽을 수 없습니다.', 500
    return render_template('index.html', ...), status

오류 처리가 두 갈래로 나뉜다는 점이 중요합니다. 잘못된 시장 이름이나 잘못된 CSV 행처럼 입력이 문제면 ValueError가 나고 400(Bad Request)으로 응답합니다. 데이터 파일을 읽을 수 없는 것처럼 서버 쪽이 문제면 500으로 응답합니다. 어느 경우든 프로그램이 죽지 않고 오류 메시지를 담은 화면을 돌려줍니다.

계산 규칙

등락률은 (종가 − 전일 종가) / 전일 종가 × 100입니다. 계산값은 반올림하지 않고 유지하며, 화면에서만 소수 둘째 자리로 표시합니다. 평균은 선택된 종목들의 동일 가중 표본 평균이므로 시장 지수 수익률과는 다릅니다. 헤더만 있는 CSV는 유효한 빈 표본으로 보고 평균을 N/A로 표시하지만, 파일이 없으면 오류입니다.

  • 한국 주식(sample2, sample4): 가격은 정수 원, 거래량은 정수 주. 005930 같은 코드는 앞의 0을 지키기 위해 문자열로 다룹니다. 평균은 ALL +0.40%, KOSPI +0.33%, KOSDAQ +0.50%입니다.
  • 미국 주식(sample1): 가격을 정수 센트로 저장하고 화면에서 USD로 바꿉니다(scale=100). 시장은 NASDAQ/NYSE, 코드는 대문자 티커입니다. ALL 평균은 +0.40%입니다.

Jinja 자동 escaping

Flask의 템플릿 엔진 Jinja는 {{ row.name }}처럼 값을 출력할 때 HTML 특수 문자를 자동으로 바꿉니다. 그래서 종목 이름에 <script> 같은 태그가 들어 있어도 실행되지 않고 글자 그대로 &lt;script&gt;로 출력됩니다. 데이터를 화면에 그대로 끼워 넣는 코드를 직접 짜지 않는 이유입니다.

SQLite에 저장하기 (sample4)

sample4는 화면을 CSV가 아니라 SQLite 데이터베이스에서 읽습니다. 데이터를 넣는 일은 웹 요청이 아니라 별도의 명령 flask --app app init-db가 맡습니다. 이 명령은 @app.cli.command('init-db')로 등록되어 있습니다.

flask --app app init-db
python app.py
  • 검증이 먼저: import_snapshot()은 모든 행을 검증한 뒤에 기존 행을 지웁니다. 중복 코드 같은 잘못된 데이터는 DB에 손대기 전에 거부됩니다.
  • 한 트랜잭션: 삭제와 삽입이 with connection: 안에서 한 번에 커밋되므로, 중간에 실패해도 직전 데이터가 그대로 남습니다.
  • 읽기 전용 연결: read_quotes()는 mode=ro로 엽니다. DB 파일이 없을 때 빈 DB를 새로 만들어 버리지 않고 오류를 내므로, 화면은 "먼저 init-db를 실행하세요"라고 안내합니다.
  • CSV를 고친 뒤에는 init-db로 다시 가져와야 화면에 반영됩니다.

database.py에는 read_quotes()가 두 번 정의되어 있습니다. Python에서는 나중 정의가 앞의 것을 덮어쓰므로 실제로 쓰이는 것은 두 번째(mode=ro) 정의입니다.

이 웹 실습에서 실행하기

실제 PC에서는 프로젝트마다 가상환경을 만들고 pip install -r requirements.txt로 Flask를 설치한 뒤 python app.py로 실행하고, 브라우저에서 http://127.0.0.1:5002 같은 주소를 엽니다. 이 웹 실습의 가상 머신에는 Flask가 이미 들어 있지만, 내 브라우저와 네트워크로 연결되어 있지 않아 브라우저로 서버에 접속할 수는 없습니다. 대신 실습용 도우미 명령 web을 씁니다. web start로 서버를 띄우면 터미널 아래에 앱 미리보기 창이 열립니다. 이 창이 브라우저 역할을 해서, 링크를 누르거나 폼에서 시장을 고르고 조회를 누르면 요청이 가상 머신 안의 서버로 전달되고 응답 화면이 다시 그려집니다. 창 위의 주소 칸에 /?market=KOSPI 같은 주소를 넣고 열기를 눌러도 됩니다. 서버를 끄면 창이 흐려집니다.

미리보기 창은 공유 폴더 /mnt/host/.web를 통해 요청과 응답을 파일로 주고받으므로, 요청 하나에 0.2~1초쯤 걸립니다. 앱의 CSS와 그림은 응답에 함께 넣어 보여 주고, 앱 페이지의 JavaScript는 실행하지 않습니다.

터미널에서 쓸 수 있는 명령은 다음과 같습니다.
