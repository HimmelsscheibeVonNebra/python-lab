Steps실행 순서

  1. ls -a; ls data

    .gitignore starts with a dot, so it only shows up with ls -a. This follows the slide's rule that README.md and .gitignore go in together from the very first commit.점으로 시작하는 .gitignore는 ls -a로만 보인다. 첫 커밋부터 README.md와 .gitignore가 함께 들어가야 한다는 슬라이드의 규칙대로다.

  2. python3 main.py

    This prints Loaded 0 records, the check output for lab step 1. That is because storage.load_records still returns only an empty list and report.format_summary returns TODO: summary. Even with TODO bodies, main.py must run.실습 1단계의 확인 출력 Loaded 0 records가 나온다. storage.load_records가 아직 빈 리스트만 돌려주고, report.format_summary는 TODO: summary를 돌려주기 때문이다. 몸체가 TODO여도 main.py는 실행되어야 한다.

  3. ls -a; cat .gitignore

    After running, a new __pycache__ folder has appeared (the compiled output of the imported modules). Generated files like this match the __pycache__/ and *.pyc patterns in .gitignore, so they do not show up in git status. .venv/, .vscode/, .DS_Store and the secrets .env and *.key are not committed either.실행 후 __pycache__ 폴더가 새로 생겼다(import한 모듈의 컴파일 결과). 이런 생성 파일은 .gitignore의 __pycache__/ 와 *.pyc 패턴에 걸려 git status에 나타나지 않는다. .venv/, .vscode/, .DS_Store, 그리고 비밀 정보 .env, *.key도 커밋하지 않는다.

  4. python3 -c 'import logic; print(logic.parse_value.__doc__)'

    A stub has its final name and its full contract, but its body is raise NotImplementedError. main.py does not call this function yet, so the program still runs. In lab step 2 you replace this name and docstring with the functions from your own design document.스텁은 최종 이름과 전체 계약을 갖추되 몸체는 raise NotImplementedError다. main.py가 이 함수를 아직 호출하지 않으므로 프로그램은 그대로 돈다. 실습 2단계에서 이 이름과 docstring을 자기 설계 문서의 함수로 바꾼다.

  5. cp report.py /tmp/report_before.py; sed -i 's/TODO: summary/No records yet/' report.py; diff -u /tmp/report_before.py report.py; python3 main.py

    This imitates the format git diff shows, using diff -u. Lines starting with - were removed, lines with + were added, and @@ gives the location. On a real PC you would check this change with git diff and save it with git commit -am "...". The second line of main.py's output changes to No records yet.git diff가 보여 주는 형식을 diff -u로 흉내 냈다. -로 시작하는 줄은 지워진 줄, +는 추가된 줄, @@는 위치다. 실제 PC에서는 이 변경 뒤 git diff로 확인하고 git commit -am "..."으로 저장한다. main.py의 두 번째 줄이 No records yet으로 바뀐다.

This virtual machine has no git, network or browser, so git init, commit and push, branches and GitHub pull requests cannot be run here. Do the lab on your own PC, where git --version works. The last step modifies report.py, so reload the page to return to the original state.이 가상 머신에는 git, 네트워크, 브라우저가 없어 git init·commit·push, 브랜치, GitHub 풀 리퀘스트는 실행할 수 없다. 실습은 git --version이 동작하는 자신의 PC에서 한다. 마지막 단계는 report.py를 수정하므로 처음 상태로 돌리려면 페이지를 새로 고친다.
