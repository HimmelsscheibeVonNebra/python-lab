The CSV input boundary

CSV cells arrive as strings. Check the schema and required fields first, and pass only validated, converted values to the analysis function.

Stock codes stay text

int("005930")  # 5930

Leading zeros are part of a stock code. Convert only the prices and volumes used in calculations to integers.

Conversion and valid values

int("-1")  # -1

Even if conversion succeeds, reject a negative volume. Prices must be greater than 0, and volume must be 0 or more.

Row rules and snapshot rules

ScopeRule
One rowReal date, valid price and volume ranges
Whole inputOne date, unique stock codes

Whether whitespace is normalized is also part of the input contract. In the MVP, parse_row handles the row rules and analyze handles the whole-input rules. In korea_market_mvp you can see a row with volume -1 rejected by parse_row, and a duplicate code on a row that the filter would drop rejected by analyze.

The minimum-volume type contract

Accept only nonnegative int values; reject bool, strings and floats. Distinguish a value passed in a direct function call from a value converted from a CLI string.

def validate_min_volume(value):
    if type(value) is not int or value < 0:
        raise ValueError("min_volume must be a nonnegative integer")
    return value

isinstance(True, int) is True, so bool has to be handled explicitly. Here type(value) is not int rejects bool as well.

Where exceptions are raised and where they are handled

Rule functions raise ValueError for contract violations. The storage module passes file and decoding failures on to its caller. The CLI converts expected failures into a user message and an exit code. Handle exceptions where the program can make a useful decision, and keep unexpected programming errors visible during development.

Failure disguised as empty data

try:
    quotes = load_quotes(path)
except Exception:
    quotes = []

Written like this, missing files and programming errors both look like valid empty input.

Failure and valid empty results

InputExpected behavior
Missing CSVFail, preserve the old report
Valid header-only CSVSucceed, generate an empty report

A completely empty (zero-byte) file is different from a header-only file.

except (OSError, ValueError, UnicodeError) as error:

최소 거래량의 자료형 계약

0 이상의 int만 허용하고 bool·문자열·실수는 거절합니다. 함수를 직접 호출할 때의 값과, CLI에서 받은 문자열을 변환한 값은 구분합니다.

def validate_min_volume(value):
    if type(value) is not int or value < 0:
        raise ValueError("min_volume must be a nonnegative integer")
    return value

isinstance(True, int)는 True이므로 bool은 따로 고려해야 합니다. 여기서는 type(value) is not int로 bool까지 거절합니다.

예외를 어디서 던지고 어디서 처리하는가

활동 C는 8분입니다. 교체가 실패하면 OSError가 호출자에게 전달될지, 출력은 OLD와 NEW 중 무엇일지, 폴더에 임시 파일이 남을지 먼저 적습니다.

활동 D는 8분입니다. 각 후보를 잡아내는 최소 입력을 만듭니다.

짝에게 후보 이름을 가리고 입력과 기대 결과만 보여 주면, 짝은 그 입력이 어떤 결함을 잡는지 설명합니다. 중복 사례는 같은 날짜·코드를 가진 두 행 중 하나만 기준 이상이 되게 만들어야 합니다. 경계값과 숨겨진 중복 사례는 프로젝트 테스트 계획(project-review.md)으로 옮깁니다. playground의 마지막 단계는 후보 A를 기준과 같은 값 100으로 잡아내는 모습입니다.
