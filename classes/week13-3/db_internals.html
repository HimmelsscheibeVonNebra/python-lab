    See the execution plan the query processor chose. Searching by the primary key gives SEARCH … USING INDEX sqlite_autoindex_quotes_1; searching by market gives SCAN quotes, which reads the whole table. After adding an index on market, the plan for the same SQL changes to SEARCH … USING INDEX quotes_market, but the result and the SQL statement stay the same. This is physical data independence: changing how data is stored does not affect the logical schema or the application (the experiment used the copy /tmp/plan.db).질의 처리기가 고른 실행 계획을 본다. 기본 키로 찾으면 SEARCH … USING INDEX sqlite_autoindex_quotes_1, market으로 찾으면 표 전체를 훑는 SCAN quotes다. market에 인덱스를 추가하면 같은 SQL의 계획이 SEARCH … USING INDEX quotes_market으로 바뀌지만 결과와 SQL 문장은 그대로다. 저장 방식이 바뀌어도 논리 스키마와 응용은 영향받지 않는 물리적 데이터 독립성이다(복사본 /tmp/plan.db에서 실험했다).

    Two users try to change the same row at the same time. When B tries to write before A has committed, it is refused with B: database is locked (with timeout=0 it fails immediately instead of waiting). B gives up its attempt with rollback(). Only after A commits can B write, so the volume goes 1000000 → 1000002, with both changes applied. This is the engine's concurrency control preventing the lost update in which one change disappeared in Session 1's file example. The final create_db.py restores the original values.두 사용자가 같은 행을 동시에 고치려 한다. A가 커밋하기 전에 B가 쓰려 하면 B: database is locked로 거절된다(timeout=0이라 기다리지 않고 바로 실패). B는 rollback()으로 시도를 접는다. A가 커밋한 뒤에야 B가 쓸 수 있어 거래량이 1000000 → 1000002로 두 번 모두 반영된다. 1차시의 파일 예제에서 한 건이 사라졌던 갱신 손실을 엔진의 동시성 제어가 막는 모습이다. 마지막에 create_db.py로 원래 값을 되돌린다.

SQLite is an embedded engine that writes a single file; in the slides' classification it is centralized (one system does all the work). The client-server, parallel and distributed architectures and the DBA permission management from the slides are not reproduced in this lab. In Week 14, Flask plays the role of the application server in a three-tier architecture.SQLite는 하나의 파일을 쓰는 내장형(embedded) 엔진이고, 슬라이드의 분류로는 한 시스템이 모든 일을 하는 중앙 집중형(centralized)이다. 슬라이드의 클라이언트-서버, 병렬, 분산 구조나 DBA 권한 관리는 이 실습에서 재현하지 않는다. 14주차의 Flask가 3계층 구조의 응용 서버 역할을 맡는다.

create_db.py 28 lines28줄 
"""Create market.db from schema.sql and load prices.csv. Safe to run again."""
import csv
import sqlite3
from pathlib import Path
 
BASE = Path(__file__).resolve().parent
INSERT = """
    INSERT INTO quotes
    VALUES (?, ?, ?, ?, ?, ?, ?)
"""
 
 
def main():
    schema = (BASE / "schema.sql").read_text(encoding="utf-8")
    with open(BASE / "prices.csv", encoding="utf-8", newline="") as f:
        rows = [tuple(r.values()) for r in csv.DictReader(f)]
    con = sqlite3.connect(BASE / "market.db")
    con.executescript(schema)
    con.execute("DELETE FROM quotes")
    con.executemany(INSERT, rows)
    con.commit()
    count = con.execute("SELECT COUNT(*) FROM quotes").fetchone()[0]
    con.close()
    print(f"market.db ready: {count} rows")
 
 
if __name__ == "__main__":
    main()
schema.sql 13 lines13줄 
CREATE TABLE IF NOT EXISTS quotes (
    date   TEXT NOT NULL,
    code   TEXT NOT NULL,
    name   TEXT NOT NULL,
    market TEXT NOT NULL,
    previous_close INTEGER NOT NULL
        CHECK (previous_close > 0),
    close  INTEGER NOT NULL
        CHECK (close > 0),
    volume INTEGER NOT NULL
        CHECK (volume >= 0),
    PRIMARY KEY (date, code)
);
