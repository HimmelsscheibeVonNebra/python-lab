Networking네트워크

Learn what IP addresses, ports and loopback are, and build a TCP echo server and client with socket. Send a GET request over a raw socket to see that HTTP is an agreement written in plain text (a protocol), exchange files with urllib.request and http.server, then build a JSON API server and client, handle network errors and try UDP. This virtual machine has no internet, so every connection stays inside 127.0.0.1 (the machine itself).IP 주소·포트·루프백을 이해하고 socket으로 TCP 에코 서버와 클라이언트를 만든다. 소켓 위로 GET 요청을 직접 보내 HTTP가 글자로 된 약속(프로토콜)임을 확인하고, urllib.request와 http.server로 파일을 주고받은 뒤, JSON API 서버와 클라이언트, 네트워크 오류 처리, UDP까지 실습한다. 이 가상 머신에는 인터넷이 없어서 모든 통신은 127.0.0.1(자기 자신) 안에서 이루어진다. Examples예제

echo ~/network/echo

The smallest server and client. The server waits for connections on port 5000 of 127.0.0.1 and sends back whatever bytes it receives; the client sends one message and prints the reply. The server runs in the background with &, and kill stops it at the end.가장 작은 서버와 클라이언트. 서버는 127.0.0.1의 5000번 포트에서 접속을 기다리다가 받은 바이트를 그대로 돌려주고, 클라이언트는 메시지 하나를 보내고 답을 출력한다. 서버는 &로 백그라운드에서 띄우고 마지막에 kill로 멈춘다.

Steps실행 순서

  1. ip addr

    The machine's network devices. Only lo (loopback) with inet 127.0.0.1 is up; there is no network card (a name like eth0). This virtual machine cannot reach the internet and can only talk to itself. On a real PC you would see one more device with an address such as 192.168.0.12.이 컴퓨터의 네트워크 장치 목록이다. lo(루프백)의 inet 127.0.0.1만 살아 있고 랜카드(eth0 같은 이름)는 없다. 이 가상 머신은 인터넷에 나갈 수 없고, 자기 자신하고만 통신할 수 있다는 뜻이다. 실제 PC라면 192.168.0.12 같은 주소를 가진 장치가 하나 더 보인다.

  2. cat /etc/hosts

    The oldest address book there is, pairing names with IP addresses. Both localhost and this machine's name, python-lab, point to 127.0.0.1. That is why writing localhost in a URL is the same as 127.0.0.1.이름과 IP 주소를 짝지은 가장 오래된 주소록이다. localhost와 이 컴퓨터의 이름 python-lab이 모두 127.0.0.1을 가리킨다. 그래서 주소 칸에 localhost라고 써도 127.0.0.1과 같다.

  3. python3 echo_server.py &

    The trailing & runs the program in the background. A server never finishes because it keeps waiting for connections; without & the terminal would be stuck with it and you could not type the next command. The server's output will show up later, mixed into this terminal.끝의 &는 프로그램을 백그라운드에서 실행한다. 서버는 접속을 기다리느라 끝나지 않는 프로그램이라서, &가 없으면 터미널이 서버에 묶여 다음 명령을 칠 수 없다. 서버의 출력은 나중에 이 터미널에 섞여 나온다.

  4. sleep 2; python3 echo_client.py hello

    Gives the server 2 seconds to start, then runs the client. Lines starting with [server] come from the background server, the [client] line from the client: two programs printing into one terminal. The server received b'hello', 5 bytes, and sent it straight back.서버가 켜질 시간을 2초 준 뒤 클라이언트를 실행한다. [server]로 시작하는 줄은 백그라운드 서버가, [client] 줄은 클라이언트가 찍었다. 한 터미널에 두 프로그램의 출력이 섞여 보이는 것이다. 서버는 5 bytes인 b'hello'를 받아 그대로 돌려주었다.

  5. python3 echo_client.py 안녕

    Sockets carry bytes, not strings. The two characters of 안녕 are 6 bytes in UTF-8 (b'\xec\x95\x88...'). The client turned the text into bytes with encode, and turned the reply back into text with decode. The server did not stop; it took the next connection.소켓은 문자열이 아니라 바이트를 주고받는다. 글자 두 개인 안녕이 UTF-8로는 6 bytes(b'\xec\x95\x88...')다. 클라이언트가 encode로 바꿔 보내고, 받은 바이트를 decode로 다시 글자로 만들었다. 서버는 꺼지지 않고 다음 접속을 받았다.

  6. netstat -tln

    The TCP ports currently waiting for connections (LISTEN). 127.0.0.1:5000 is our echo server. Because its address is 127.0.0.1, only programs on this machine can connect.지금 접속을 기다리는(LISTEN) TCP 포트 목록이다. 127.0.0.1:5000이 우리 에코 서버다. 주소가 127.0.0.1이므로 이 컴퓨터 안에서만 접속할 수 있다.

  7. python3 - <<'EOF' text = "안녕" data = text.encode("utf-8") print(data, len(text), len(data)) print(data.decode("utf-8")) EOF

    str and bytes side by side: len(text), the number of characters, is 2; len(data), the number of bytes, is 6. Encode before sending over the network, decode after receiving. Both sides must use the same encoding (utf-8) or the text comes out garbled.str과 bytes를 따로 확인한다. 글자 수 len(text)는 2, 바이트 수 len(data)는 6이다. 네트워크로 보내기 전에는 encode, 받은 뒤에는 decode한다. 양쪽이 같은 인코딩(utf-8)을 써야 글자가 깨지지 않는다.

  8. kill %1

    %1 is this terminal's background job number 1 (the echo server). Unless you kill it, the server keeps holding port 5000. The jobs command lists the background jobs.%1은 이 터미널의 1번 백그라운드 작업(에코 서버)이다. kill로 멈추지 않으면 서버는 계속 5000번 포트를 차지한다. jobs 명령으로 백그라운드 작업 목록을 볼 수 있다.

If you start the server twice, the second one fails with OSError: [Errno 98] Address in use (a typical Linux PC words it Address already in use), because only one program can hold a port. Find the leftover server with jobs, stop it with kill %1 and start again.서버를 두 번 띄우면 두 번째 서버는 OSError: [Errno 98] Address in use로 실패한다(일반 리눅스 PC에서는 Address already in use라고 나온다). 한 포트는 한 프로그램만 차지할 수 있기 때문이다. 이때는 jobs로 남은 서버를 찾아 kill %1로 멈춘 뒤 다시 실행한다.

raw_http ~/network/http

HTTP is an agreement in plain text (a protocol). Start the web server that comes with Python (python3 -m http.server), send a GET request line over a socket yourself, and read the response as status line, headers and body. Send the same request with nc to see the raw response.HTTP는 글자로 된 약속(프로토콜)이다. 파이썬에 들어 있는 웹 서버(python3 -m http.server)를 띄우고, 소켓 위로 GET 요청 줄을 직접 보내 돌아온 응답을 상태 줄·헤더·본문으로 나누어 읽는다. nc로 같은 요청을 보내 응답 원문도 본다.

Steps실행 순서

  1. ls site

    The files the web server will hand out. The server treats this folder as the root (/) of the site, so a request for /hello.txt gets site/hello.txt.웹 서버가 내보낼 파일들이다. 서버는 이 폴더를 웹사이트의 뿌리(/)로 삼아 /hello.txt 요청에 site/hello.txt를 돌려준다.

  2. python3 -m http.server 8000 --bind 127.0.0.1 --directory site &

    Runs the standard library module http.server as a program: port 8000, bound to 127.0.0.1 only (--bind), serving the files in site (--directory). A web server without writing a line of code.표준 라이브러리의 http.server 모듈을 프로그램처럼 실행한다. 8000번 포트, 127.0.0.1에만 묶고(--bind), site 폴더의 파일을 내보낸다(--directory). 코드 한 줄 없이 웹 서버가 생긴다.

  3. sleep 3; python3 raw_get.py /hello.txt

    The request: line is everything we sent: the request line GET /hello.txt HTTP/1.0, a Host header, and an empty line (\r\n\r\n) to finish. The first line of the response, HTTP/1.0 200 OK, is the status line, then come the name = value headers, and after an empty line the 57-byte body. The line 127.0.0.1 - - [...] "GET /hello.txt HTTP/1.0" 200 is the server's access log. The Date and Last-Modified values change on every run.request: 줄이 우리가 보낸 전부다. GET /hello.txt HTTP/1.0 요청 줄, Host 헤더, 그리고 빈 줄(\r\n\r\n)로 끝난다. 응답의 첫 줄 HTTP/1.0 200 OK가 상태 줄이고, 이어서 이름 = 값 헤더들, 빈 줄 뒤에 본문 57바이트가 온다. 127.0.0.1 - - [...] "GET /hello.txt HTTP/1.0" 200 줄은 서버가 남긴 접속 기록이다. Date와 Last-Modified 값은 실행할 때마다 다르다.

  4. printf 'GET /index.html HTTP/1.0\r\n\r\n' | nc 127.0.0.1 8000

    The same thing without Python. nc (netcat) sends its input over a socket and prints the bytes that come back unchanged, so you can see the empty line between headers and body. Content-type: text/html says the body is HTML; a browser sees this and draws a web page instead of showing text.파이썬 없이 같은 일을 해 본다. nc(netcat)는 받은 글자를 소켓으로 보내고 돌아온 바이트를 그대로 화면에 찍는다. 헤더와 본문 사이의 빈 줄이 보인다. Content-type: text/html은 본문이 HTML이라는 표시이고, 브라우저는 이것을 보고 글자 대신 웹 페이지로 그린다.

  5. python3 raw_get.py /nothing.txt | head -n 3

    Asking for a file that does not exist still connects, and the server answers normally, only the status line is HTTP/1.0 404 File not found. A status code is the server saying "I got your request, and here is how it went". head -n 3 keeps the first three lines.없는 파일을 요청해도 연결은 성공하고 서버는 정상적으로 답한다. 다만 상태 줄이 HTTP/1.0 404 File not found다. 상태 코드는 '요청은 받았지만 결과가 이렇다'는 서버의 대답이다. head -n 3으로 앞 세 줄만 본다.

  6. kill %1

    Stops the web server. From now on a request to port 8000 is refused outright (the errors example shows this).웹 서버를 멈춘다. 이제 8000번 포트에 요청하면 연결 자체가 거절된다(errors 예제에서 확인한다).

On a real PC, start the same server and type http://127.0.0.1:8000/ into the browser's address bar: index.html opens as a web page. A browser is just a program that sends the same GET request text as this example.실제 PC에서는 같은 서버를 띄운 뒤 브라우저 주소 칸에 http://127.0.0.1:8000/ 을 넣어 보면 index.html이 웹 페이지로 열린다. 브라우저도 결국 이 예제와 똑같은 GET 요청 글자를 보내는 프로그램이다.

fetch ~/network/http

Open a URL with urllib.request.urlopen and the standard library builds the request and splits the response for you. Take the result apart with status, headers and read(), and when the Content-Type is application/json, turn it into a dictionary with json.loads.urllib.request.urlopen으로 URL 하나를 열면 요청 만들기, 응답 나누기를 표준 라이브러리가 대신 해 준다. status, headers, read()로 결과를 꺼내고, Content-Type이 application/json이면 json.loads로 딕셔너리로 바꾼다.

Steps실행 순서

  1. python3 -m http.server 8000 --bind 127.0.0.1 --directory site &

    Starts the same web server as in raw_http.raw_http와 같은 웹 서버를 다시 띄운다.

  2. sleep 3; python3 fetch.py http://127.0.0.1:8000/hello.txt

    From the response object urlopen returned we took status 200, reason OK and the Content-Type header text/plain. read() returns bytes, so the length is 57 bytes; the program decodes them before printing. In the server's log the request line now says HTTP/1.1, because urllib wrote the request.urlopen이 돌려준 응답 객체에서 status 200, reason OK, Content-Type 헤더 text/plain을 꺼냈다. read()는 bytes를 돌려주므로 길이는 57 bytes이고, decode한 뒤 출력했다. 서버 기록의 요청 줄이 이번에는 HTTP/1.1이다. urllib이 만든 요청이기 때문이다.

  3. python3 fetch.py http://localhost:8000/data.json

    Writing localhost reaches the same server (/etc/hosts). The server labelled the .json file Content-Type: application/json, so fetch.py turned the body into a dictionary with json.loads and printed one key and value per line. temperature is the integer 3, not a string.주소를 localhost로 써도 같은 서버에 닿는다(/etc/hosts). 서버가 .json 파일에 Content-Type: application/json을 붙였으므로 fetch.py는 json.loads로 본문을 딕셔너리로 바꾸고 키와 값을 한 줄씩 찍었다. temperature는 문자열이 아니라 정수 3이다.

  4. python3 - <<'EOF' from urllib.request import urlopen with urlopen("http://127.0.0.1:8000/") as response: print(response.status, response.headers["Content-Type"]) html = response.read().decode("utf-8") for line in html.splitlines(): if "<h1>" in line: print(line) EOF

    Asking for just / makes the server return the folder's index.html (200 text/html). A web page is only text, so a string method finds the <h1>It works!</h1> line.경로 /만 요청하면 서버는 폴더 안의 index.html을 돌려준다(200 text/html). 웹 페이지도 그저 글자이므로 문자열 메서드로 <h1>It works!</h1> 줄을 찾아낼 수 있다.

  5. wget -q -O - http://127.0.0.1:8000/data.json

    The command-line downloader wget fetches the same JSON. -O - means print to the screen instead of saving a file. The server does not care who is asking, as long as they keep to the agreement (HTTP).명령줄 다운로드 도구 wget으로도 같은 JSON을 받는다. -O -는 파일로 저장하지 않고 화면에 출력하라는 뜻이다. 서버는 누가 요청했는지 신경 쓰지 않는다. 약속(HTTP)만 지키면 된다.

  6. kill %1

    Stops the web server.웹 서버를 멈춘다.

On a PC with internet access the same fetch.py opens real web addresses, for example python3 fetch.py https://www.python.org/ — urlopen even handles the encryption of https. This virtual machine has no internet, so such addresses fail as in the errors example.인터넷이 되는 PC에서는 같은 fetch.py로 진짜 웹 주소를 열 수 있다. 예를 들어 python3 fetch.py https://www.python.org/ 처럼 https 주소도 urlopen이 암호화까지 처리해 준다. 이 가상 머신에는 인터넷이 없어서 이런 주소는 errors 예제처럼 실패한다.

json_api ~/network/api

A small JSON API built on http.server's BaseHTTPRequestHandler. GET /memos lists the memos, GET /memos/<id> returns one, POST /memos adds a new one. It answers with a fitting status code (200, 201, 400, 404) and a JSON body, and api_client.py sends and receives JSON with urllib.request.Request.http.server의 BaseHTTPRequestHandler로 만드는 작은 JSON API. GET /memos는 메모 목록, GET /memos/<id>는 메모 하나, POST /memos는 새 메모를 추가한다. 상황에 맞는 상태 코드(200, 201, 400, 404)와 JSON 본문으로 답하고, api_client.py는 urllib.request.Request로 JSON을 보내고 받는다.

Steps실행 순서

  1. python3 api_server.py &

    Starts the memo API server on port 8080 in the background. The memos live only in the Python list memos, so they are gone when the server stops.메모 API 서버를 8080번 포트에서 백그라운드로 띄운다. 메모는 파이썬 리스트 memos에만 들어 있으므로 서버를 끄면 사라진다.

  2. sleep 3; wget -q -O - http://127.0.0.1:8080/memos; echo

    do_GET answered GET /memos. The body is the JSON array [{"id": 1, "text": "buy milk"}]. [server] GET /memos -> 200 is the one-line log from our own log_request. The final echo adds a newline, since the body has none and the prompt would stick to it.GET /memos에 do_GET이 응답했다. 본문은 JSON 배열 [{"id": 1, "text": "buy milk"}]이다. [server] GET /memos -> 200은 log_request를 고쳐 쓴 한 줄 기록이다. 끝의 echo는 본문 끝에 줄바꿈이 없어서 프롬프트가 붙지 않도록 넣었다.

  3. python3 api_client.py

    The client's call("GET", "/memos") returns a tuple (status code, decoded JSON): (200, [{'id': 1, 'text': 'buy milk'}]). udp ~/network/udp

UDP sends one self-contained chunk (a datagram) at a time, like a letter, with no connection. The receiver ends by itself after three datagrams on port 5005; the sender sends each command-line word as one datagram. Even when nobody is receiving, the sender finishes without an error.연결 없이 편지처럼 한 덩어리(데이터그램)씩 보내는 UDP. 수신기는 5005번 포트에서 데이터그램 세 개를 받으면 스스로 끝나고, 송신기는 명령줄 단어 하나를 데이터그램 하나로 보낸다. 받는 쪽이 없어도 보내는 쪽은 오류 없이 끝난다.

"""A tiny JSON API: a memo board kept in memory.
 
GET  /memos        -> 200, every memo
GET  /memos/<id>   -> 200, one memo (404 if there is none)
POST /memos        -> 201, add {"text": "..."} (400 if the body is wrong)
"""
import json
from http.server import BaseHTTPRequestHandler, HTTPServer
 
HOST = "127.0.0.1"
PORT = 8080
 
memos = [{"id": 1, "text": "buy milk"}]
 
 
class MemoHandler(BaseHTTPRequestHandler):
    def send_json(self, status, data):
        body = json.dumps(data, ensure_ascii=False).encode("utf-8")
        self.send_response(status)                       # status line
        self.send_header("Content-Type", "application/json; charset=utf-8")
        self.send_header("Content-Length", str(len(body)))
        self.end_headers()                               # empty line
        self.wfile.write(body)                           # body
 
    def do_GET(self):
        if self.path == "/memos":
            self.send_json(200, memos)
        elif self.path.startswith("/memos/"):
            memo_id = self.path.removeprefix("/memos/")
            for memo in memos:
                if str(memo["id"]) == memo_id:
                    self.send_json(200, memo)
                    return
            self.send_json(404, {"error": f"no memo {memo_id}"})
        else:
            self.send_json(404, {"error": "not found"})
 
    def do_POST(self):
        if self.path != "/memos":
            self.send_json(404, {"error": "not found"})
            return
        length = int(self.headers.get("Content-Length", 0))
        raw = self.rfile.read(length)                    # the request body
        try:
            text = json.loads(raw)["text"]
        except (json.JSONDecodeError, KeyError, TypeError):
            self.send_json(400, {"error": 'send JSON like {"text": "..."}'})
            return
        memo = {"id": len(memos) + 1, "text": text}
        memos.append(memo)
        self.send_json(201, memo)
 
    def log_request(self, code="-", size="-"):
        # one short line per request instead of the default access log
        print(f"[server] {self.command} {self.path} -> {code}")
 
 
print(f"[server] memo API on http://{HOST}:{PORT}")
HTTPServer((HOST, PORT), MemoHandler).serve_forever()

Networking네트워킹

This topic is networking. For two programs to exchange data they have to agree on where the other one is (an IP address and a port), which channel to use (TCP or UDP), and how to interpret the bytes that arrive (a protocol such as HTTP). We start by building the smallest possible server and client with the socket module, and on top of that we write an HTTP request by hand to see that HTTP is really an agreement written in plain text. Then we do the same in a few lines with the standard library's urllib.request and http.server, build a small API server that exchanges JSON, and finally look at handling network errors and at UDP. The practice programs are echo, raw_http, fetch, json_api, errors and udp.

The virtual machine in this lab has no network card, so it cannot reach the internet. Instead, server and client run on the same machine and talk over loopback (127.0.0.1, the machine itself), which every computer has. The code works unchanged on a real network; what changes on a real PC is summarised near the end.

Clients and Servers

Most network programs play one of two roles. A server waits at a known place for requests and answers them; a client makes the first contact and sends a request. A web browser is a client, the program that hands out a web site is a server. One computer can run both at the same time, and that is exactly what we do in this lab.

  client                              server
  (makes contact)                     (waits)
       |  ---- request --------->      |
       |  <--- response ---------      |

IP Addresses, Ports and Loopback

IP Address: Which Computer

An IP address is the number that identifies a computer (strictly, a network device) on a network. An IPv4 address is four numbers from 0 to 255 joined by dots, like 192.168.0.12. Names that are easy for people to remember (www.python.org) are turned into IP addresses by a service called DNS. The oldest name list of all is the file /etc/hosts.

Port: Which Program on That Computer

Several servers can run on one computer at once, so an IP address alone is not enough. A port, a number from 0 to 65535, says which program on the computer the data is for. If the IP address is the building's street address, the port is the flat number. That is why an address always travels as an (IP, port) pair, and in Python it is written as a tuple such as ("127.0.0.1", 5000). Only one program at a time can hold a given port.

PortCommon use
22SSH (remote login)
80HTTP (the web)
443HTTPS (the encrypted web)
5000, 8000, 8080Numbers development servers like to use; in this lab the echo server, the file server and the API server

Ports below 1024 need administrator rights to open, so practice servers usually pick a number of 1024 or above.

Loopback: 127.0.0.1 and localhost

127.0.0.1 is a special address meaning "this very computer", and its name is localhost. Data sent there never goes out on a cable; the operating system turns it straight around. So you can test servers and clients without any internet. The first step of echo, ip addr, shows that this virtual machine has nothing but lo (loopback).

Network communication is built from layers, each doing one job. An upper layer does not need to know how the layer below does its work. In this topic we work directly with the top two.

TCP Sockets: an Echo Server and Client

What Is a Socket?

A socket is the end point where a program meets the network. Just as opening a file gives you a file object to read and write, creating a socket gives you a socket object to send and receive bytes. socket.socket(socket.AF_INET, socket.SOCK_STREAM) creates "a TCP socket using IPv4 addresses". TCP sets up a connection first and guarantees that the bytes you send arrive complete and in order, a bit like a phone call.

The Calls on Each Side

Reading the Server

import socket

HOST = "127.0.0.1"   # loopback: only programs on this computer can connect
PORT = 5000

with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as server:
    server.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
    server.bind((HOST, PORT))
    server.listen()
    print(f"[server] listening on {HOST}:{PORT}")

    while True:
        conn, addr = server.accept()          # waits for the next client
        with conn:
            data = conn.recv(1024)            # bytes, at most 1024 of them
            conn.sendall(data)                # echo the same bytes back

The server socket (server) is only a doorkeeper. Each time a client connects, accept() returns a new socket conn just for that client, plus the client's address addr; the actual conversation happens over conn. Thanks to while True the server goes back to waiting for the next client after each one. SO_REUSEADDR avoids an "address already in use" error when you stop the server and start it again right away.

Reading the Client

import socket
import sys

message = " ".join(sys.argv[1:]) or "hello"

with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as client:
    client.connect(("127.0.0.1", 5000))
    data = message.encode("utf-8")            # str -> bytes
    client.sendall(data)
    reply = client.recv(1024)

print(f"[client] sent {len(data)} bytes, got back: {reply.decode('utf-8')}")

The command-line arguments (sys.argv) become the message: run python3 echo_client.py hello and message is "hello".

Bytes and Encodings

What travels over a network is always bytes (bytes). Turn a string into bytes with encode("utf-8") before sending, and turn received bytes back into a string with decode("utf-8"). An English letter is 1 byte, but a Korean character is 3 bytes in UTF-8, so "안녕" ("hi") is 2 characters and 6 bytes. Byte values print with a leading b, as in b'hello'.

text = "안녕"
data = text.encode("utf-8")
print(data, len(text), len(data))   # b'\xec\x95\x88\xeb\x85\x95' 2 6
print(data.decode("utf-8"))         # 안녕

Protocols: HTTP Is an Agreement in Plain Text

What Is a Protocol?

TCP carries bytes faithfully but has no idea what they mean. A protocol is the rule both sides agree on in advance: what to send, in which order and in which format. The echo server's rule was simply "send back what you get". The web's rule is HTTP. HTTP requests and responses are text a person can read, with lines ending in \r\n.

The Shape of a Request and a Response

request (client -> server)
  GET /hello.txt HTTP/1.0          request line: method, path, version
  Host: 127.0.0.1:8000             headers (name: value), any number
                                   empty line = end of headers

response (server -> client)
  HTTP/1.0 200 OK                  status line: version, status code, reason
  Content-type: text/plain         headers
  Content-Length: 57
                                   empty line
  Hello from the server!           body (57 bytes)
  안녕하세요, 서버입니다.

Headers describe the body. Content-Type gives its kind (text/plain, text/html, application/json) and Content-Length its size in bytes. A browser looks at Content-Type to decide whether to show text or draw a web page. Header names ignore case, so the Content-type that http.server sends is the same header as Content-Type.

Status Codes

CodeNameMeaning
200OKSuccess
201CreatedSomething new was created (a successful POST)
400Bad RequestThe request is malformed
404Not FoundNo such path

The first digit gives the broad class: 2xx success, 3xx go elsewhere, 4xx the client's fault, 5xx the server's fault. Note that a 404 is still a normal answer sent by the server; it is not the same as failing to connect at all.

Python's Web Server: http.server

The standard library includes a simple web server that hands out the files in a folder. -m runs a module as a program.

python3 -m http.server 8000 --bind 127.0.0.1 --directory site &

It listens on port 8000 and treats the site folder as the root (/) of the site: a request for /hello.txt gets site/hello.txt, a request for / gets site/index.html. Each request leaves an access log line such as 127.0.0.1 - - [date] "GET /hello.txt HTTP/1.0" 200 -. It is meant for development and practice, not for running a real service.

Sending a GET Over a Raw Socket

raw_get.py in raw_http does by hand what a browser does: it builds the request text, sends it, receives until the server closes the connection, and splits head from body at the first empty line (\r\n\r\n).

request = f"GET {path} HTTP/1.0\r\nHost: {HOST}:{PORT}\r\n\r\n"

with socket.create_connection((HOST, PORT)) as sock:
    sock.sendall(request.encode("ascii"))
    chunks = []
    while True:                     # read until the server closes the connection
        chunk = sock.recv(4096)
        if not chunk:
            break
        chunks.append(chunk)

response = b"".join(chunks)
head, _, body = response.partition(b"\r\n\r\n")
lines = head.decode("iso-8859-1").split("\r\n")
print("status line:", lines[0])

socket.create_connection((HOST, PORT)) is a shortcut that creates the socket and calls connect in one go. recv may return only part of the data, so the loop keeps collecting until it gets empty bytes (b""), which means the other side closed the connection. With HTTP/1.0 the server closes the connection after sending the whole response.

You can run the same experiment without Python. nc (netcat) sends its input over a socket and prints whatever comes back.

printf 'GET /index.html HTTP/1.0\r\n\r\n' | nc 127.0.0.1 8000

A Small JSON API Server

APIs and Methods

A web page returns HTML for people to read; an API returns data (usually JSON) for programs to read. The method of a request says what you want to do.

RequestMeaningSuccessful answer
GET /memosGive me the list of memos200 with a JSON array
GET /memos/2Give me memo number 2200 with a JSON object (404 if there is none)
POST /memosCreate a new memo from the JSON in the body201 with the new memo (400 if the body is wrong)

The Server: BaseHTTPRequestHandler

Subclass BaseHTTPRequestHandler from http.server and give it do_GET and do_POST methods; the server calls the one matching the request's method. The request path is in self.path, the headers in self.headers, the body is read from self.rfile, and the response is written in the order status line, headers, empty line, body. The shape of the HTTP response you saw earlier becomes the order of the method calls.

def send_json(self, status, data):
    body = json.dumps(data, ensure_ascii=False).encode("utf-8")
    self.send_response(status)                       # status line
    self.send_header("Content-Type", "application/json; charset=utf-8")
    self.send_header("Content-Length", str(len(body)))
    self.end_headers()                               # empty line
    self.wfile.write(body)                           # body

def do_POST(self):
    length = int(self.headers.get("Content-Length", 0))
    raw = self.rfile.read(length)                    # the request body
    try:
        text = json.loads(raw)["text"]
    except (json.JSONDecodeError, KeyError, TypeError):
        self.send_json(400, {"error": 'send JSON like {"text": "..."}'})
        return
    memo = {"id": len(memos) + 1, "text": text}
    memos.append(memo)
    self.send_json(201, memo)

The body is read for exactly the number of bytes the Content-Length header announced. Data from a client is checked, not trusted: if it is not JSON or has no text key, the server answers 400 instead of crashing. ensure_ascii=False sends Korean text as the characters themselves instead of escapes like 우. The memos live only in a Python list, so they vanish when the server stops; to keep them you would save them to a file or a database.

Handling Network Errors

A file is usually just there, but a network can fail at any moment: the server may be down, slow, or at the wrong address. Each kind of failure raises a different exception. In errors you trigger them one by one.

SituationWith socketWith urlopen
No server waiting on that portConnectionRefusedErrorURLError (reason: Connection refused)
The server answered, but with 404, 500, ...(you read the status line yourself)HTTPError (code: 404)
Connected, but no answer comesTimeoutError (old name socket.timeout)TimeoutError or URLError
The name cannot be turned into an IP addresssocket.gaierrorURLError (reason: [Errno -3] ...)
 
def fetch_text(url, timeout=3):
    try:
        with urlopen(url, timeout=timeout) as response:
            return response.read().decode("utf-8")
    except HTTPError as error:          # the server answered with 4xx/5xx
        print(f"HTTP error {error.code} {error.reason}: {url}")
    except URLError as error:           # no answer: refused, unknown host, ...
        print(f"cannot reach {url}: {error.reason}")
    except TimeoutError:                # connected, but the reply never came
        print(f"timed out after {timeout} s: {url}")
    return None

Three things to remember:

  • The order of except: HTTPError is a subclass of URLError. If URLError came first it would catch the 404 too, so the more specific HTTPError goes first.
  • Always set a timeout: without timeout, a server that never answers freezes your program forever. silent_server.py accepts connections but never replies, to show why a timeout matters. With sockets, set it with create_connection(addr, timeout=2) or sock.settimeout(2).
  • What the user should see: instead of a traceback, one line saying what failed and why, and then the program carries on. If it makes sense, try again a little later.

Opening http://example.com/ in this virtual machine fails with [Errno -3] Try again because there is no DNS. On a PC with internet access the same code fetches the page.

UDP: Letters Without a Connection

UDP does not set up a connection; it throws data one chunk (a datagram) at a time. Change the socket type to SOCK_DGRAM and, with no listen, accept or connect, exchange data with sendto(data, addr) and recvfrom(1024).

# receiver
sock = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
sock.bind(("127.0.0.1", 5005))
data, addr = sock.recvfrom(1024)      # one whole datagram + sender

# sender
sock = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
sock.sendto("하나".encode("utf-8"), ("127.0.0.1", 5005))

What Changes on a Real PC

  • Real IP addresses: besides loopback, a real PC has a device with an address like 192.168.0.12. Other computers on the same Wi-Fi connect to that address.
  • 127.0.0.1 versus 0.0.0.0: a server bound to 127.0.0.1 accepts connections only from the same computer. To let other computers in, bind to 0.0.0.0 (every device). That opens it to the outside, so keeping practice servers on 127.0.0.1 is the safe choice.
  • Firewalls: the operating system's firewall may block incoming connections. On Windows or macOS a window may ask whether to allow a server the first time it starts.
  • DNS and https: with internet access, urlopen("https://www.python.org/") opens named addresses and encrypted https just the same. In this virtual machine it fails because there is no DNS.
  • Two terminals: instead of & and kill %1, run the server in one terminal window and the client in another. Stop the server with Ctrl+C.
  • A browser: start python3 -m http.server and open http://127.0.0.1:8000/ in your browser. The browser's requests show up in the server's access log.

Common Mistakes

  • Sending a string as is: sock.sendall("hello") gives TypeError: a bytes-like object is required, not 'str'. Send "hello".encode("utf-8") or b"hello".
  • Starting the client before the server: you get ConnectionRefusedError. Start the server first and wait a moment until it is ready.
  • Starting a server twice on the same port: OSError: [Errno 98] Address in use (on a typical Linux PC, Address already in use). Find the leftover server with jobs and stop it with kill %1.
  • Running a server without &: the terminal looks frozen. Nothing is broken; the server is waiting. Stop it with Ctrl+C and run it again with &.
  • Trusting one recv to get everything: TCP is a stream of bytes, so a message may arrive in several pieces. One recv is enough for the short messages of the echo example, but for longer data either keep receiving until the end, as raw_get.py does, or use a rule that announces the length first (Content-Length).
  • Waiting without a timeout: a server that never answers freezes your program forever. Always set a time limit, as in urlopen(url, timeout=5).
  • Mistaking a 404 for a failed connection: a 404 is a normal answer from the server. Handle HTTPError and URLError separately.

Summary

  • An address is an (IP, port) pair. 127.0.0.1 (localhost) is the machine itself.
  • A TCP server does bind → listen → accept → recv/sendall, a client connect → sendall → recv. What travels is bytes, so encode/decode.
  • A protocol is an agreement on what the bytes mean. HTTP is text made of a request line (or status line), headers, an empty line and a body.
  • urllib.request.urlopen is an HTTP client and http.server an HTTP server. JSON goes back and forth with json.dumps/json.loads.
  • Network code sets a timeout and catches HTTPError, URLError, TimeoutError and ConnectionRefusedError.
  • UDP sends datagrams with neither a connection nor guaranteed delivery.

IP 주소, 포트, 루프백

IP 주소: 어느 컴퓨터인가

IP 주소는 네트워크 안에서 컴퓨터(정확히는 네트워크 장치)를 가리키는 번호입니다. IPv4 주소는 192.168.0.12처럼 0–255 사이의 수 네 개를 점으로 이은 모양입니다. 사람이 외우기 쉬운 이름(www.python.org)은 DNS라는 서비스가 IP 주소로 바꿔 줍니다. 가장 오래된 이름표는 /etc/hosts 파일입니다.

포트: 그 컴퓨터의 어느 프로그램인가

한 컴퓨터에서 여러 서버가 동시에 돌 수 있으므로 IP 주소만으로는 부족합니다. 포트는 0–65535 사이의 번호로, 컴퓨터 안의 어느 프로그램에게 가는 데이터인지 정합니다. IP 주소가 건물 주소라면 포트는 호수입니다. 그래서 주소는 늘 (IP, 포트) 한 쌍으로 다니며, 파이썬에서도 ("127.0.0.1", 5000) 같은 튜플로 씁니다. 한 포트는 한 번에 한 프로그램만 차지할 수 있습니다.

루프백: 127.0.0.1과 localhost

127.0.0.1은 "바로 이 컴퓨터"를 뜻하는 특별한 주소이고, 이름은 localhost입니다. 여기로 보낸 데이터는 랜선으로 나가지 않고 운영체제 안에서 곧바로 되돌아옵니다. 그래서 인터넷이 없어도 서버와 클라이언트를 시험할 수 있습니다. echo의 첫 단계 ip addr에서 이 가상 머신에 lo(루프백) 하나만 있는 것을 확인합니다.

TCP 소켓: 에코 서버와 클라이언트

소켓이란

소켓은 프로그램이 네트워크와 만나는 끝점입니다. 파일을 열면 파일 객체로 읽고 쓰듯, 소켓을 만들면 소켓 객체로 바이트를 보내고 받습니다. socket.socket(socket.AF_INET, socket.SOCK_STREAM)은 "IPv4 주소를 쓰는 TCP 소켓"을 만듭니다. TCP는 연결을 먼저 맺고, 보낸 바이트가 빠짐없이 순서대로 도착하도록 보장합니다. 전화와 비슷합니다.

서버와 클라이언트가 부르는 함수

서버클라이언트의미
socket()socket()소켓을 만든다
bind((HOST, PORT))이 주소와 포트를 내 것으로 정한다
listen()접속을 받을 준비를 한다
accept()connect((HOST, PORT))연결이 맺어진다. accept는 클라이언트가 올 때까지 기다린다
recv(1024)sendall(data)클라이언트가 보내고 서버가 받는다
sendall(data)recv(1024)서버가 답하고 클라이언트가 받는다
close()close()연결을 닫는다(with가 대신 해 준다)

서버 코드 읽기

import socket

HOST = "127.0.0.1"   # loopback: only programs on this computer can connect
PORT = 5000

with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as server:
    server.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
    server.bind((HOST, PORT))
    server.listen()
    print(f"[server] listening on {HOST}:{PORT}")

    while True:
        conn, addr = server.accept()          # waits for the next client
        with conn:
            data = conn.recv(1024)            # bytes, at most 1024 of them
            conn.sendall(data)                # echo the same bytes back

서버 소켓(server)은 문지기 역할만 합니다. accept()는 클라이언트가 접속할 때마다 그 클라이언트 전용의 새 소켓 conn과 상대 주소 addr을 돌려주고, 실제 대화는 conn으로 합니다. while True 덕분에 한 클라이언트를 처리한 뒤 다음 클라이언트를 기다립니다. SO_REUSEADDR은 서버를 끄고 바로 다시 켤 때 포트가 아직 사용 중이라는 오류를 피하게 해 줍니다.

프로토콜: HTTP는 글자로 된 약속

프로토콜이란

TCP는 바이트를 정확히 날라 줄 뿐, 그 바이트가 무슨 뜻인지는 모릅니다. 양쪽이 "무엇을 어떤 순서와 형식으로 보낼지"를 미리 정한 규칙이 프로토콜입니다. 에코 서버의 규칙은 "받은 것을 그대로 돌려준다"뿐이었습니다. 웹의 규칙은 HTTP입니다. HTTP 요청과 응답은 사람이 읽을 수 있는 글자이고, 줄은 \r\n으로 끝납니다.

요청과 응답의 모양

요청 (클라이언트 -> 서버)
  GET /hello.txt HTTP/1.0          요청 줄: 메서드, 경로, 버전
  Host: 127.0.0.1:8000             헤더(이름: 값), 여러 줄 가능
                                   빈 줄 = 헤더 끝

응답 (서버 -> 클라이언트)
  HTTP/1.0 200 OK                  상태 줄: 버전, 상태 코드, 이유
  Content-type: text/plain         헤더
  Content-Length: 57
                                   빈 줄
  Hello from the server!           본문(바이트 57개)
  안녕하세요, 서버입니다.

헤더는 본문에 대한 설명입니다. Content-Type은 본문의 종류(text/plain, text/html, application/json)를, Content-Length는 본문의 바이트 수를 알려 줍니다. 브라우저는 Content-Type을 보고 글자를 보여 줄지 웹 페이지로 그릴지 정합니다. 헤더 이름은 대소문자를 가리지 않으므로 http.server가 보내는 Content-type과 Content-Type은 같은 헤더입니다.

소켓으로 직접 GET 보내기

raw_http의 raw_get.py는 브라우저가 하는 일을 손으로 합니다. 요청 글자를 만들어 보내고, 서버가 연결을 닫을 때까지 받은 뒤, 첫 빈 줄(\r\n\r\n)을 기준으로 머리와 본문을 나눕니다.

request = f"GET {path} HTTP/1.0\r\nHost: {HOST}:{PORT}\r\n\r\n"

with socket.create_connection((HOST, PORT)) as sock:
    sock.sendall(request.encode("ascii"))
    chunks = []
    while True:                     # read until the server closes the connection
        chunk = sock.recv(4096)
        if not chunk:
            break
        chunks.append(chunk)

response = b"".join(chunks)
head, _, body = response.partition(b"\r\n\r\n")
lines = head.decode("iso-8859-1").split("\r\n")
print("status line:", lines[0])

socket.create_connection((HOST, PORT))은 소켓 만들기와 connect를 한 번에 하는 지름길입니다. recv는 한 번에 일부만 돌려줄 수 있으므로, 빈 바이트(b"")가 올 때까지, 즉 상대가 연결을 닫을 때까지 반복해서 모읍니다. HTTP/1.0에서는 서버가 응답을 다 보낸 뒤 연결을 닫습니다.

파이썬 없이도 같은 실험을 할 수 있습니다. nc(netcat)는 입력을 소켓으로 보내고 받은 것을 그대로 찍는 도구입니다.

printf 'GET /index.html HTTP/1.0\r\n\r\n' | nc 127.0.0.1 8000

서버: BaseHTTPRequestHandler

http.server의 BaseHTTPRequestHandler를 상속한 클래스에 do_GET, do_POST 메서드를 만들면, 서버가 요청의 메서드에 맞는 것을 불러 줍니다. 요청 경로는 self.path, 헤더는 self.headers, 본문은 self.rfile에서 읽고, 응답은 상태 줄, 헤더, 빈 줄, 본문 순서로 씁니다. 앞에서 본 HTTP 응답의 모양이 그대로 메서드 호출 순서가 됩니다.

def send_json(self, status, data):
    body = json.dumps(data, ensure_ascii=False).encode("utf-8")
    self.send_response(status)                       # status line
    self.send_header("Content-Type", "application/json; charset=utf-8")
    self.send_header("Content-Length", str(len(body)))
    self.end_headers()                               # empty line
    self.wfile.write(body)                           # body

def do_POST(self):
    length = int(self.headers.get("Content-Length", 0))
    raw = self.rfile.read(length)                    # the request body
    try:
        text = json.loads(raw)["text"]
    except (json.JSONDecodeError, KeyError, TypeError):
        self.send_json(400, {"error": 'send JSON like {"text": "..."}'})
        return
    memo = {"id": len(memos) + 1, "text": text}
    memos.append(memo)
    self.send_json(201, memo)

본문은 Content-Length 헤더가 알려 준 바이트 수만큼 정확히 읽습니다. 클라이언트가 보낸 데이터는 믿지 않고 검사합니다. JSON이 아니거나 text 키가 없으면 서버가 죽는 대신 400으로 답합니다. ensure_ascii=False는 한글을 우 같은 이스케이프 대신 글자 그대로 내보냅니다. 메모는 파이썬 리스트에만 있으므로 서버를 끄면 사라집니다. 오래 보관하려면 파일이나 데이터베이스에 저장해야 합니다.

def fetch_text(url, timeout=3):
    try:
        with urlopen(url, timeout=timeout) as response:
            return response.read().decode("utf-8")
    except HTTPError as error:          # the server answered with 4xx/5xx
        print(f"HTTP error {error.code} {error.reason}: {url}")
    except URLError as error:           # no answer: refused, unknown host, ...
        print(f"cannot reach {url}: {error.reason}")
    except TimeoutError:                # connected, but the reply never came
        print(f"timed out after {timeout} s: {url}")
    return None

세 가지를 기억합니다.

  • except 순서: HTTPError는 URLError의 자식 클래스입니다. URLError를 먼저 쓰면 404도 그쪽에서 잡혀 버리므로 더 구체적인 HTTPError를 먼저 씁니다.
  • timeout은 필수: timeout을 주지 않으면 답하지 않는 서버 앞에서 프로그램이 영원히 멈춥니다. silent_server.py는 연결만 받고 답하지 않는 서버로, timeout의 필요성을 보여 줍니다. 소켓에서는 create_connection(addr, timeout=2)나 sock.settimeout(2)로 정합니다.
  • 무엇을 사용자에게 보여 줄까: Traceback 대신 무엇이 왜 실패했는지 한 줄로 알려 주고, 프로그램은 다음 일을 계속합니다. 필요하면 잠시 뒤 다시 시도합니다.

이 가상 머신에서 http://example.com/을 열면 DNS가 없어서 [Errno -3] Try again으로 실패합니다. 인터넷이 되는 PC에서는 같은 코드가 페이지를 받아 옵니다.

UDP: 연결 없는 편지

UDP는 연결을 맺지 않고 데이터를 한 덩어리(데이터그램)씩 던집니다. 소켓 종류만 SOCK_DGRAM으로 바꾸고, listen, accept, connect 없이 sendto(data, addr)와 recvfrom(1024)로 주고받습니다.

# receiver
sock = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
sock.bind(("127.0.0.1", 5005))
data, addr = sock.recvfrom(1024)      # one whole datagram + sender

# sender
sock = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
sock.sendto("하나".encode("utf-8"), ("127.0.0.1", 5005))

udp의 마지막 단계에서 수신기가 끝난 뒤에도 송신기가 아무 오류 없이 "보냈다"고 말하는 것을 확인합니다. 받았는지 확인하는 일은 프로그램이 직접 해야 합니다.

실제 PC에서 달라지는 것

  • 진짜 IP 주소: 실제 PC에는 루프백 말고도 192.168.0.12 같은 주소를 가진 장치가 있습니다. 같은 Wi-Fi의 다른 컴퓨터는 그 주소로 접속합니다.
  • 127.0.0.1과 0.0.0.0: 서버를 127.0.0.1에 bind하면 같은 컴퓨터에서만 접속할 수 있습니다. 다른 컴퓨터에서 접속하게 하려면 0.0.0.0(모든 장치)에 bind합니다. 외부에 공개하는 것이므로 연습용 서버는 127.0.0.1에 두는 것이 안전합니다.
  • 방화벽: 운영체제의 방화벽이 들어오는 접속을 막을 수 있습니다. Windows나 macOS에서 서버를 처음 띄우면 허용할지 묻는 창이 뜨기도 합니다.
  • DNS와 https: 인터넷이 되면 urlopen("https://www.python.org/")처럼 이름으로 된 주소와 암호화된 https도 그대로 열립니다. 이 가상 머신에서는 DNS가 없어서 실패합니다.
  • 터미널 두 개: &와 kill %1 대신 터미널 창 하나에서 서버를 실행하고 다른 창에서 클라이언트를 실행할 수 있습니다. 서버는 Ctrl+C로 멈춥니다.
  • 브라우저: python3 -m http.server를 띄우고 브라우저에서 http://127.0.0.1:8000/을 열어 보세요. 브라우저가 보내는 요청이 서버의 접속 기록에 그대로 찍힙니다.

흔한 실수

  • 문자열을 그대로 보내기: sock.sendall("hello")는 TypeError: a bytes-like object is required, not 'str'입니다. "hello".encode("utf-8")나 b"hello"를 보냅니다.
  • 서버보다 클라이언트를 먼저 실행하기: ConnectionRefusedError가 납니다. 서버를 먼저 띄우고 준비될 때까지 잠깐 기다립니다.
  • 같은 포트로 서버를 두 번 띄우기: OSError: [Errno 98] Address in use(일반 리눅스 PC에서는 Address already in use). jobs로 남은 서버를 찾아 kill %1로 멈춥니다.
  • 서버를 & 없이 실행하기: 터미널이 멈춘 것처럼 보입니다. 고장이 아니라 서버가 기다리는 중입니다. Ctrl+C로 멈추고 &를 붙여 다시 실행합니다.
  • recv 한 번이면 다 온다고 믿기: TCP는 바이트의 흐름이라서 보낸 메시지가 여러 번에 나뉘어 도착할 수 있습니다. 에코 예제는 짧은 메시지라 한 번으로 충분하지만, 긴 데이터는 raw_get.py처럼 끝날 때까지 반복해서 받거나 길이(Content-Length)를 먼저 알려 주는 규칙을 둡니다.
  • timeout 없이 기다리기: 답하지 않는 서버 앞에서 영원히 멈춥니다. urlopen(url, timeout=5)처럼 항상 시간을 정합니다.
  • 404를 연결 실패로 착각하기: 404는 서버가 보낸 정상적인 대답입니다. HTTPError와 URLError를 구분해서 처리합니다.

정리

  • 주소는 (IP, 포트) 한 쌍입니다. 127.0.0.1(localhost)은 자기 자신입니다.
  • TCP 서버는 bind → listen → accept → recv/sendall, 클라이언트는 connect → sendall → recv입니다. 오가는 것은 bytes이므로 encode/decode합니다.
  • 프로토콜은 바이트의 의미에 대한 약속입니다. HTTP는 요청 줄(또는 상태 줄), 헤더, 빈 줄, 본문으로 된 글자입니다.
  • urllib.request.urlopen은 HTTP 클라이언트, http.server는 HTTP 서버입니다. JSON은 json.dumps/json.loads로 주고받습니다.
  • 네트워크 코드는 timeout을 정하고, HTTPError, URLError, TimeoutError, ConnectionRefusedError를 잡습니다.
  • UDP는 연결도 도착 보장도 없는 데이터그램입니다.
