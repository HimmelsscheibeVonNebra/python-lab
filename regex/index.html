Examples예제

first_search ~/regex/basics

Find the mobile numbers in a sentence twice: once with split and if statements, once with the regular expression r"010-\d{4}-\d{4}". See why patterns are written as raw strings, how re.search, match, fullmatch, findall and finditer differ, and the None you get when nothing matches.문장에서 휴대전화 번호를 찾는 일을 split과 조건문으로 한 번, 정규 표현식 r"010-\d{4}-\d{4}"로 한 번 풀어 비교한다. raw 문자열을 쓰는 이유, re.search·match·fullmatch·findall·finditer의 차이, 일치가 없을 때 돌아오는 None을 확인한다.

Steps실행 순서

  1. python3 first_search.py

    in only says True or False. The split version has to remove brackets and commas, strip the full stop, and check the length and digits of all three pieces one by one before it finds the two numbers. The regex version just describes the shape in one line and gets the same result. Both 02-123-4567 and the order number 2026-1126-0001 are filtered out. The first number starts at character 4 and ends before character 17.in은 True/False만 알려 준다. split 버전은 괄호와 쉼표를 지우고, 마침표를 떼고, 세 조각의 길이와 숫자 여부를 하나하나 검사해야 두 번호를 찾는다. 정규 표현식 버전은 모양을 한 줄로 적을 뿐인데 같은 결과가 나온다. 02-123-4567과 주문번호 2026-1126-0001은 둘 다 걸러졌다. 첫 번호는 4번 글자에서 시작해 17번 앞에서 끝난다.

  2. python3 - <<'EOF' print(len("\n"), len(r"\n")) print(r"\d{4}") print("C:\temp\new") print(r"C:\temp\new") EOF

    In an ordinary string \n is one character (a newline), but r"\n" is two: a backslash and n (1 2). Written as an ordinary string, C:\temp\new turns \t into a tab and \n into a newline and the path falls apart. Regexes are full of backslashes (\d, \b, ...), so always write patterns as r"...".보통 문자열에서 \n은 줄바꿈 한 글자지만 r"\n"은 역슬래시와 n 두 글자다(1 2). C:\temp\new를 보통 문자열로 쓰면 \t는 탭, \n은 줄바꿈이 되어 경로가 깨진다. 정규 표현식은 \d, \b처럼 역슬래시를 많이 쓰므로 패턴은 항상 r"..."로 쓴다.

  3. python3 - <<'EOF' import re print(re.findall("\d+", "a1b22")) EOF

    Leave out the r and Python 3.14 prints SyntaxWarning: "\d" is an invalid escape sequence. It happens to work for now (['1', '22']), but as the warning says this will become an error. When you see it, put an r in front of the pattern.r을 빠뜨리면 Python 3.14는 SyntaxWarning: "\d" is an invalid escape sequence를 낸다. 지금은 우연히 ['1', '22']로 동작하지만 경고 문구대로 앞으로는 오류가 될 예정이다. 경고가 보이면 패턴 앞에 r을 붙인다.

  4. python3 - <<'EOF' import re s = "주문 010-1234-5678" print(re.search(r"\d+", s)) print(re.match(r"\d+", s)) print(re.fullmatch(r"\d+", "2026")) print(re.fullmatch(r"\d+", "2026년")) EOF

    search finds the first match anywhere in the string: span=(3, 6), match='010'. match only tries at the very start, so it fails on '주' and returns None. fullmatch needs the whole string to fit the pattern: "2026" matches, "2026년" gives None. For input validation, use fullmatch.search는 문자열 어디에서든 첫 일치를 찾는다: span=(3, 6), match='010'. match는 맨 앞에서만 시도하므로 '주'에서 실패해 None이다. fullmatch는 문자열 전체가 패턴과 같아야 해서 "2026"은 일치하고 "2026년"은 None이다. 입력 검증에는 fullmatch를 쓴다.

  5. python3 - <<'EOF' import re text = "사과 3개, 배 12개, 귤 7개" print(re.findall(r"\d+", text)) for m in re.finditer(r"\d+", text): print(m.group(), m.span()) EOF

    findall returns a list of the matched strings, ['3', '12', '7']. finditer hands out Match objects one at a time, so you also get each position (span). Convert with int() when you need numbers.findall은 일치한 문자열의 리스트 ['3', '12', '7']를 돌려준다. finditer는 Match 객체를 하나씩 내주므로 위치(span)까지 알 수 있다. 숫자가 필요하면 int()로 바꾼다.

  6. python3 - <<'EOF' import re m = re.search(r"\d+", "숫자가 없는 문장") print(m) print(m.group()) EOF

    With no match, search returns None, and calling .group() on None raises AttributeError: 'NoneType' object has no attribute 'group'.일치가 없으면 search는 None을 돌려주고, None에 .group()을 부르면 AttributeError: 'NoneType' object has no attribute 'group'이 난다.

  7. python3 - <<'EOF' import re for text in ["숫자가 없는 문장", "방 번호 301"]: m = re.search(r"\d+", text) if m: print(text, "->", m.group()) else: print(text, "-> no number") EOF

    The fix: check with if m: first. A Match object counts as true and None as false.고친 버전: if m:으로 먼저 확인한다. Match 객체는 참, None은 거짓으로 취급된다.

The AttributeError in the fifth step is on purpose. That re.search can return None is the most common regex mistake, so always check with if m: before using the result.다섯 번째 단계의 AttributeError는 일부러 낸 오류다. re.search가 None을 돌려줄 수 있다는 사실은 정규 표현식에서 가장 자주 만나는 실수이므로, 결과를 쓰기 전에 항상 if m:으로 확인한다.

try_pattern ~/regex/patterns

A small test bench: give it a pattern and a sentence on the command line and it wraps every match in [ ] and lists the positions. Experiment in turn with character classes (\d \w \s [...] [^...]), quantifiers (? * + {m,n}), anchors (^ $ \b), the dot and escaping, greedy and non-greedy matching, and |.명령줄로 받은 패턴과 문장에 대해 일치한 부분을 [ ]로 감싸 보여 주고 위치를 나열하는 작은 실험 도구다. 문자 클래스(\d \w \s [...] [^...]), 수량자(? * + {m,n}), 앵커(^ $ \b), 점과 이스케이프, 탐욕적·비탐욕적 일치, |를 차례로 실험한다.

Steps실행 순서

  1. python3 try_pattern.py

    Without arguments it prints its usage. sys.argv[1] is the pattern and sys.argv[2] the sentence.인자 없이 실행하면 사용법을 보여 준다. sys.argv[1]이 패턴, sys.argv[2]가 문장이다.

  2. python3 try_pattern.py '\d' 'Room 101, 2nd floor' python3 try_pattern.py '\d+' 'Room 101, 2nd floor'

    \d is a single digit, so 1, 0, 1 and 2 match separately: four matches. Adding + (one or more) makes \d+ take a run of digits as one piece: '101' and '2'.\d는 숫자 한 글자라서 1, 0, 1, 2가 따로따로 네 번 일치한다. +(한 번 이상)를 붙인 \d+는 이어진 숫자를 한 덩어리로 잡아 '101'과 '2' 두 개가 된다.

  3. python3 try_pattern.py '[aeiou]' 'regular expression' python3 try_pattern.py '[^a-z ]' 'Hello, World 42!'

    Square brackets mean 'one character from this set'. [aeiou] catches only the vowels. A ^ right after the opening bracket negates the set, so [^a-z ] catches every character that is neither a lowercase letter nor a space: H , W 4 2 !.대괄호는 '이 중 한 글자'다. [aeiou]는 모음만 잡는다. 대괄호 맨 앞의 ^는 부정이라 [^a-z ]는 소문자도 공백도 아닌 글자, 즉 H , W 4 2 !를 잡는다.

  4. python3 try_pattern.py '\w+' 'snake_case, kebab-case, 한글123' python3 try_pattern.py '\S+' 'snake_case, kebab-case, 한글123'

    \w is a letter, digit or underscore. The underscore is included but the hyphen is not, so kebab and case split apart. Python's \w is Unicode-aware, so 한글123 is one word. \S (anything but whitespace) grabs everything between spaces, commas included.\w는 글자·숫자·밑줄이다. 밑줄은 포함되지만 하이픈은 아니어서 kebab과 case가 갈라진다. Python의 \w는 유니코드라 한글123도 한 단어다. \S(공백이 아닌 것)는 쉼표까지 붙여 공백 사이를 통째로 잡는다.

  5. python3 try_pattern.py 'colou?r' 'color colour colouur' python3 try_pattern.py '\d{3,4}' '12 123 1234 12345'

    ? means the previous character is optional (zero or one), so color and colour match but colouur does not. {3,4} means 3 to 4 repetitions. 12 is too short, and from 12345 only the leading 1234 is taken: quantifiers grab as much as they can (4).?는 앞의 글자가 없거나 하나, 그래서 color와 colour는 잡히고 colouur는 아니다. {3,4}는 3~4번 반복이다. 12는 너무 짧고, 12345에서는 앞의 1234만 잡힌다. 수량자는 가능한 한 많이(4개) 가져간다.

  6. python3 try_pattern.py '^\d+' '42 apples, 7 pears, total 49' python3 try_pattern.py '\d+$' '42 apples, 7 pears, total 49' python3 try_pattern.py '\bcat\b' 'cat concat cats cat.'

    Anchors match positions, not characters. ^ is the start of the string, so only 42 matches; $ is the end, so only 49. \b is a word boundary: the cat inside concat and cats is skipped, leaving the two cats that stand alone.앵커는 글자가 아니라 위치를 잡는다. ^는 문자열의 시작이라 42만, $는 끝이라 49만 일치한다. \b는 단어 경계라서 concat과 cats 속의 cat은 빠지고 앞뒤가 단어 밖인 cat 두 개만 남는다.

  7. python3 try_pattern.py '3.14' 'pi 3.14 vs 3714' python3 try_pattern.py '3\.14' 'pi 3.14 vs 3714'

    . is any character except a newline, which is why 3.14 also matches 3714. To find a real full stop, escape it as \.. The same goes for ( ) [ ] { } * + ? ^ $ | and \..은 줄바꿈을 뺀 아무 글자다. 그래서 3.14가 3714에도 일치한다. 진짜 마침표를 찾으려면 \.로 이스케이프한다. ( ) [ ] { } * + ? ^ $ | \도 마찬가지다.

  8. python3 try_pattern.py '<.+>' '<b>bold</b> and <i>it</i>' python3 try_pattern.py '<.+?>' '<b>bold</b> and <i>it</i>'

    Greedy matching: .+ runs to the end and backs up only to the last >, so the whole sentence is one match. The non-greedy .+? stops at the nearest >, giving four matches: '<b>' '</b>' '<i>' '</i>'.탐욕적 일치: .+는 끝까지 갔다가 마지막 >까지 되돌아오므로 문장 전체가 한 번에 잡힌다. ?를 붙인 .+?는 비탐욕적이라 가장 가까운 >에서 멈춰 '<b>' '</b>' '<i>' '</i>' 네 개가 된다.

  9. python3 try_pattern.py 'cat|dog' 'cat, dog, catalog, hotdog' python3 try_pattern.py '\b(cat|dog)\b' 'cat, dog, catalog, hotdog'

    | means 'or'. On its own it also catches the cat and dog inside catalog and hotdog. Group it in brackets and surround it with \b: the | now splits only inside the brackets, and just the standalone words cat and dog remain.|는 '또는'이다. 그냥 쓰면 catalog와 hotdog 속의 cat, dog까지 잡는다. 괄호로 묶어 \b로 감싸면 |가 괄호 안에서만 나뉘어 독립된 단어 cat과 dog만 남는다.

Always wrap the pattern and the sentence in single quotes, so the shell passes characters like \, *, $, < and | to Python untouched. Try your own patterns too: guess the result first, then run it.패턴과 문장은 항상 작은따옴표로 감싼다. 셸이 \, *, $, <, | 같은 글자를 건드리지 않고 그대로 Python에 넘긴다. 직접 다른 패턴도 넣어 보며 결과를 먼저 예상한 뒤 실행해 본다.

reformat ~/regex/groups

Split the dates and phone numbers in schedule.txt into parts with groups. Use numbered groups (\1 \2 \3), named groups (?P<name>...) and backreferences in re.sub to rewrite the dates as DD.MM.YYYY, and a function to hide the middle of each phone number as ****. Also experiment with how findall treats groups, re.split, and backreferences inside a pattern.schedule.txt의 날짜와 전화번호를 그룹으로 나눠 꺼낸다. 번호 그룹(\1 \2 \3)과 이름 그룹(?P<name>...), re.sub의 역참조로 날짜를 DD.MM.YYYY로 바꾸고, 함수로 전화번호 가운데를 ****로 가린다. findall과 그룹의 관계, re.split, 패턴 안의 역참조도 실험한다.

Steps실행 순서

  1. cat schedule.txt

    A three-line schedule. Every line has a YYYY-MM-DD date, and two lines have a mobile number.세 줄짜리 일정표다. 줄마다 YYYY-MM-DD 날짜가 있고, 두 줄에는 휴대전화 번호가 있다.

  2. python3 reformat.py

    group(0) is the whole match, groups() a tuple of what each pair of brackets caught: ('2026', '03', '02'). Being a tuple, it can be unpacked. Named groups come out with p["mid"] or p.group("last"), and groupdict() gives a dictionary. r"\3.\2.\1" joins the third, second and first groups in reverse to make 02.03.2026. When you pass a function, it is called for every match and the string it returns takes the match's place: 010-****-5678.group(0)은 일치 전체, groups()는 괄호마다 잡힌 부분의 튜플('2026', '03', '02')이다. 튜플이라 언패킹도 된다. 이름 그룹은 p["mid"]나 p.group("last")로 꺼내고 groupdict()는 딕셔너리로 준다. r"\3.\2.\1"은 세 번째·두 번째·첫 번째 그룹을 거꾸로 이어 02.03.2026을 만든다. 함수를 넘기면 일치마다 그 함수가 불리고, 돌려준 문자열이 그 자리에 들어간다: 010-****-5678.

  3. python3 - <<'EOF' import re text = "2026-03-02, 2026-04-20" print(re.findall(r"\d{4}-\d{2}-\d{2}", text)) print(re.findall(r"(\d{4})-(\d{2})-(\d{2})", text)) print(re.findall(r"(\d{4})-(?:\d{2})-(?:\d{2})", text)) EOF

    A common trap: when the pattern has groups, findall returns the groups instead of the whole match. No groups gives strings, several give tuples, one gives just that group (['2026', '2026']). To group without capturing, use (?:...).흔한 함정: 패턴에 그룹이 있으면 findall은 일치 전체가 아니라 그룹을 돌려준다. 그룹이 없으면 문자열, 여러 개면 튜플, 하나면 그 그룹만(['2026', '2026']). 묶기만 하고 잡지 않으려면 (?:...)를 쓴다.

  4. python3 - <<'EOF' import re date = re.compile(r"(?P<y>\d{4})-(?P<m>\d{2})-(?P<d>\d{2})") print(date.sub(r"\g<d>/\g<m>/\g<y>", "due 2026-06-15")) print(repr(date.sub("\3.\2.\1", "due 2026-06-15"))) print(re.subn(r"\d", "#", "PIN 4821, room 301")) EOF

    In the replacement string a named group is written \g<name>: due 15/06/2026. Forget the r on the replacement and \3 becomes character code 3, giving invisible characters: 'due \x03.\x02.\x01'. re.subn returns the result together with the number of replacements (7).이름 그룹은 바꿀 문자열에서 \g<이름>으로 부른다: due 15/06/2026. 바꿀 문자열에 r을 빠뜨리면 \3은 문자 코드 3이 되어 'due \x03.\x02.\x01'처럼 보이지 않는 글자로 바뀐다. re.subn은 결과와 바꾼 횟수(7)를 함께 준다.

Regular Expressions · Text Processing정규 표현식 · 텍스트 처리

This chapter is about regular expressions (regex for short). A regular expression is a small language for writing down the shape of text, such as "three digits, a dash, four digits". Once the shape is written down, Python's re module can find it (search, findall), split text on it (split) and rewrite it (sub). We start by seeing where in and split run out of steam, learn the pattern syntax piece by piece with a small test bench, and then move on to groups and substitution, input validation and its limits, analysing a web server log, and processing Korean text. The practice programs are first_search, try_pattern, reformat, validate, log_report and hangul.

Why Regular Expressions?

Where in and split Fall Short

The string methods strip, lower, split and in are enough when you are dealing with fixed characters. But once you need to find a shape rather than fixed characters, as in "find every mobile number starting with 010", the code grows quickly. "010-" in text only tells you yes or no, and after splitting into words with split you still have to remove brackets and commas, split again on the dash, and check each piece's length and digits.

found = []
for word in text.replace("(", " ").replace(",", " ").split():
    word = word.strip(".")
    parts = word.split("-")
    if (len(parts) == 3 and parts[0] == "010"
            and len(parts[1]) == 4 and len(parts[2]) == 4
            and parts[1].isdigit() and parts[2].isdigit()):
        found.append(word)

With a regular expression the same job is one line describing the shape. \d is one digit and {4} means "four times".

import re

pattern = r"010-\d{4}-\d{4}"
print(re.findall(pattern, text))   # ['010-1234-5678', '010-9876-5432']

A regex is not always the answer. For finding fixed text or splitting on spaces, in, startswith and split are easier to read and faster. Reach for a regex when the text has a shape: numbers, dates, log lines.

Raw Strings r"..."

Regular expressions are full of backslashes: \d, \w, \b. In an ordinary string, though, Python interprets backslashes first: "\n" becomes one newline character and "\b" one backspace character. A raw string, with an r in front, leaves backslashes alone. That is why patterns are always written as r"...".

print(len("\n"), len(r"\n"))    # 1 2
print("C:\temp\new")            # \t is a tab, \n a newline: the path breaks
print(r"C:\temp\new")           # C:\temp\new

Forget the r and Python 3.14 prints SyntaxWarning: "\d" is an invalid escape sequence. It happens to work for now, but it is going to become an error. You can see the warning yourself in the third step of first_search.

Functions of the re Module

Finding: search, match, fullmatch

All three return a Match object when they match and None when they do not. They differ in where the match has to be.

import re

s = "주문 010-1234-5678"
print(re.search(r"\d+", s))            # <re.Match object; span=(3, 6), match='010'>
print(re.match(r"\d+", s))             # None: only tries at the start
print(re.fullmatch(r"\d+", "2026"))    # match: the whole string is digits
print(re.fullmatch(r"\d+", "2026년"))  # None

On a Match object, group() is the matched text, start() and end() are positions, and span() is a tuple of the two. Like a slice, end() is the position after the match.

m = re.search(r"010-\d{4}-\d{4}", text)
print(m.group(), m.start(), m.end())   # 010-1234-5678 4 17

Checking for None

Call m.group() when nothing matched and you get AttributeError: 'NoneType' object has no attribute 'group', the most common regex error of all. Check with if m: before using the result: a Match object is true and None is false.

m = re.search(r"\d+", text)
if m:
    print(m.group())
else:
    print("no number")

Finding All: findall, finditer

findall returns the matched strings as a list; finditer hands out Match objects one at a time. When you also need positions, use finditer.

text = "사과 3개, 배 12개, 귤 7개"
print(re.findall(r"\d+", text))        # ['3', '12', '7']
for m in re.finditer(r"\d+", text):
    print(m.group(), m.span())         # 3 (3, 4)  12 (9, 11)  7 (16, 17)

Character Classes

Square brackets mean "one character from this set". Inside, - writes a range, and a ^ right at the start negates the set. \d, \w and \s are shorthands for common classes; the capitals \D, \W and \S are their opposites. \w includes the underscore but not the hyphen, so kebab-case splits into two words.

$ python3 try_pattern.py '\w+' 'snake_case, kebab-case, 한글123'
  marked [snake_case], [kebab]-[case], [한글123]

Quantifiers

A quantifier applies to the single character (or group) right before it: in colou?r the ? applies only to the u. Quantifiers are greedy by default and take as much as they can, which is why \d{3,4} takes 1234 out of 12345.

$ python3 try_pattern.py '\d{3,4}' '12 123 1234 12345'
  marked 12 [123] [1234] [1234]5

Anchors and Word Boundaries

^, $ and \b match positions, not characters. \b sits between a word character and a non-word character (or the end of the string). Use it to find "cat" without the cat inside concat or cats.

$ python3 try_pattern.py '\bcat\b' 'cat concat cats cat.'
  marked [cat] concat cats [cat].

Greedy and Non-Greedy Matching

Looking for HTML tags with <.+>: it starts at the first <, .+ runs to the end of the sentence, and then it backs up one character at a time until it finds a >. The result is the whole sentence up to the last >. Put a ? after the quantifier and it becomes non-greedy, stopping at the nearest >.

$ python3 try_pattern.py '<.+>' '<b>bold</b> and <i>it</i>'
  marked [<b>bold</b> and <i>it</i>]
$ python3 try_pattern.py '<.+?>' '<b>bold</b> and <i>it</i>'
  marked [<b>]bold[</b>] and [<i>]it[</i>]

An even more precise approach is to repeat "anything but the delimiter". <[^>]+> repeats only characters that are not >, so it never needs to back up. The \[([^\]]+)\] in the log pattern works the same way.

Or (|) and Brackets

| has the lowest precedence, so \bcat|dog\b means "\bcat or dog\b". Use brackets to group it the way you mean: \b(cat|dog)\b.

Groups and Substitution

Numbered and Named Groups

Whatever sits inside brackets can be pulled out separately. Groups are numbered 1, 2, 3 in the order of their opening brackets, and group(0) is the whole match. With many groups the numbers get confusing, so give them names with (?P<name>...) and read them with m["name"]. That is how reformat takes apart the dates and phone numbers in schedule.txt.

DATE = re.compile(r"(\d{4})-(\d{2})-(\d{2})")
PHONE = re.compile(r"(?P<head>01[0-9])-(?P<mid>\d{3,4})-(?P<last>\d{4})")

m = DATE.search(text)
print(m.groups())                  # ('2026', '03', '02')
year, month, day = m.groups()

p = PHONE.search(text)
print(p["mid"], p.group("last"))   # 1234 5678
print(p.groupdict())               # {'head': '010', 'mid': '1234', 'last': '5678'}

findall and Groups

When the pattern has groups, findall returns the groups instead of the whole match: the group's string if there is one group, tuples if there are several. To group without capturing, use (?:...).

text = "2026-03-02, 2026-04-20"
re.findall(r"\d{4}-\d{2}-\d{2}", text)          # ['2026-03-02', '2026-04-20']
re.findall(r"(\d{4})-(\d{2})-(\d{2})", text)    # [('2026', '03', '02'), ('2026', '04', '20')]
re.findall(r"(\d{4})-(?:\d{2})-(?:\d{2})", text)  # ['2026', '2026']

re.sub with Backreferences

re.sub(pattern, replacement, string) returns a new string with every match replaced. In the replacement, \1 and \2 stand for what the groups caught, and \g<name> for a named group. The replacement needs an r too: without it, "\3" becomes character code 3 and an invisible character is inserted.

print(DATE.sub(r"\3.\2.\1", "2026-03-02 개강"))   # 02.03.2026 개강

date = re.compile(r"(?P<y>\d{4})-(?P<m>\d{2})-(?P<d>\d{2})")
print(date.sub(r"\g<d>/\g<m>/\g<y>", "due 2026-06-15"))   # due 15/06/2026
print(re.subn(r"\d", "#", "PIN 4821, room 301"))  # ('PIN ####, room ###', 7)

re.sub with a Function

Pass a function as the replacement and it is called with the Match object for every match; the string it returns takes the match's place. Use this when the replacement differs from match to match. The function below prints as many * as the middle part has digits.

def mask(m):
    return m["head"] + "-" + "*" * len(m["mid"]) + "-" + m["last"]

print(PHONE.sub(mask, "담당 김민지 010-1234-5678"))   # 담당 김민지 010-****-5678

re.split and Backreferences in a Pattern

str.split knows only one separator; re.split uses a pattern as the separator. Inside a pattern, \1 means "exactly the text group 1 caught", so you can find a word written twice in a row.

re.split(r"\s*[,;/]\s*", "사과, 배;귤  /감 ,  포도")   # ['사과', '배', '귤', '감', '포도']
re.findall(r"\b(\w+) \1\b", "this is is a test test")  # ['is', 'test']

The Limits of Regex Validation

A regex checks the shape only. The results above show its limits:

  • Dates: even a careful pattern that limits months to 01–12 and days to 01–31 accepts 2026-02-31. Putting the length of every month and leap years into a pattern would make it unreadable. So validate.py checks only the shape with a regex and lets datetime.date(year, month, day) decide whether the day exists (it raises ValueError if not).
  • Email: the standard allows so many forms of address that a complete regex is practically unusable. A practical pattern only filters out clearly broken input; the real check is sending a confirmation message. Because \w is Unicode, 홍길동@예시.한국 passes too; whether to accept it is the program's decision.
  • Phone numbers: the right shape does not mean the number is in service. With two -?, 010-12345678 (only one dash) passes as well. The more you allow, the more of these cases slip in.

Remember the rule: check the shape with a regex and the meaning with code.

A Log Analyzer

Taking One Log Line Apart

A web server writes one log line per request. The access.log of log_report has 40 lines like this:

192.168.0.12 - - [26/Nov/2026:09:18:05 +0900] "GET /static/app.js HTTP/1.1" 200 40213

Client IP, the time in square brackets, the request in quotes (method, path, protocol), status code, response size. report.py writes this shape over several lines with re.VERBOSE and names every part it needs.

LINE = re.compile(r"""
    (?P<ip>\d{1,3}(?:\.\d{1,3}){3})       # 192.168.0.12
    \s-\s-\s
    \[(?P<day>[^:\]]+):(?P<hour>\d{2}):\d{2}:\d{2}[^\]]*\]\s
    "(?P<method>[A-Z]+)\s(?P<path>\S+)\s[^"]*"\s
    (?P<status>\d{3})\s
    (?P<size>\d+|-)
""", re.VERBOSE)

An IP is "1 to 3 digits, then (a dot and 1 to 3 digits) three times": the repeated part is grouped with (?:...) and given {3}. Inside the brackets and quotes, "anything but the closing symbol" ([^\]], [^"]) avoids the greedy-matching trap.

Read the whole file as one string and ^ matches only once, at the very start. You need re.MULTILINE for it to match at every line.

Korean Text

The Unicode Range [가-힣]

The 11,172 precomposed Hangul syllables form one unbroken block of Unicode from U+AC00 (가) to U+D7A3 (힣), so [가-힣] alone covers every complete Hangul syllable. Single letters such as ㅋ and ㅠ (compatibility jamo) live in another block (U+3131–U+3163) and need their own class, [ㄱ-ㅎㅏ-ㅣ].

print(hex(ord("가")), hex(ord("힣")))          # 0xac00 0xd7a3
re.findall(r"[가-힣]", "한글 ㅎㅏㄴ 漢字 abc")       # ['한', '글']
re.findall(r"[ㄱ-ㅎㅏ-ㅣ]", "한글 ㅎㅏㄴ 漢字 abc")   # ['ㅎ', 'ㅏ', 'ㄴ']

hangul picks Hangul words, jamo (ㅋㅋㅋ, ㅠㅠ), English words and star ratings out of product reviews, and builds clean sentences with the symbols and jamo removed.

\w Is Unicode

In Python 3, \w, \d and \b in str patterns follow Unicode: Hangul and accented letters such as ï are word characters. If you want English letters and digits only, pass re.ASCII or spell it out as [A-Za-z0-9_].

re.findall(r"\w+", "파이썬3 최고! naïve_code")            # ['파이썬3', '최고', 'naïve_code']
re.findall(r"\w+", "파이썬3 최고! naïve_code", re.ASCII)  # ['3', 'na', 've_code']

A Limit: Particles Cannot Be Told by Shape

To count "배송이" and "배송은" as the same word, you might write a pattern that strips the particle at the end. It works for 배송이, 품질은, 포장도 and 고기를, but cuts "나이" (age) down to "나": whether a final "이" is a particle or part of the word cannot be told from the shape alone. Analysing Korean words is a job for a morphological analyser with a dictionary; regexes are for the clean-up before that (removing symbols, picking out numbers and jamo).

josa = re.compile(r"([가-힣]+?)(은|는|이|가|을|를|도)?")
for w in ["배송이", "품질은", "포장도", "고기를", "나이"]:
    print(w, "->", josa.fullmatch(w)[1])   # 배송 품질 포장 고기 나(!)

Common Mistakes

  • Leaving out the r. "\b" is a backspace character, not a word boundary. Write both patterns and replacements as r"...".
  • Not checking for None. Chaining re.search(...).group() raises AttributeError when nothing matches.
  • Validating with search or match. To check the whole input, use fullmatch.
  • Not escaping the dot. . is any character. A real full stop is \. (or [.] inside brackets).
  • Being surprised by a greedy .*. Use .*? or [^delimiter]*.
  • Forgetting that findall returns groups. To group without capturing, use (?:...).
  • Trying to do everything with a regex. Whether a date exists or an email arrives is checked with code and other means. For nested structures like HTML or JSON, use a real parser (html.parser, json).

Summary and Exercises

  • A regular expression is a language for the shape of text; the re module finds it (search, findall, finditer), checks it (fullmatch), splits on it (split) and rewrites it (sub).
  • Character classes say "which character", quantifiers "how many times", anchors "where".
  • Groups pull out parts of a match; backreferences and functions rewrite them.
  • Give frequently used patterns a name with re.compile, and comment long ones with re.VERBOSE.

왜 정규 표현식인가

in과 split의 한계

문자열 메서드 strip, lower, split, in은 정해진 글자를 다룰 때 충분합니다. 그러나 "010으로 시작하는 휴대전화 번호를 모두 찾아라"처럼 정해진 글자가 아니라 모양을 찾아야 하면 코드가 금방 길어집니다. "010-" in text는 있는지 없는지만 알려 주고, split으로 단어를 나눈 뒤에는 괄호와 쉼표를 지우고, 대시로 다시 나누고, 조각마다 길이와 숫자 여부를 검사해야 합니다.

found = []
for word in text.replace("(", " ").replace(",", " ").split():
    word = word.strip(".")
    parts = word.split("-")
    if (len(parts) == 3 and parts[0] == "010"
            and len(parts[1]) == 4 and len(parts[2]) == 4
            and parts[1].isdigit() and parts[2].isdigit()):
        found.append(word)

정규 표현식으로는 같은 일을 모양 한 줄로 적습니다. \d는 숫자 한 글자, {4}는 "네 번"입니다.

import re

pattern = r"010-\d{4}-\d{4}"
print(re.findall(pattern, text))   # ['010-1234-5678', '010-9876-5432']

정규 표현식이 늘 정답은 아닙니다. 고정된 글자를 찾거나 공백으로 나누는 정도라면 in, startswith, split이 더 읽기 쉽고 빠릅니다. 모양이 있는 텍스트(번호, 날짜, 로그 줄)를 다룰 때 정규 표현식을 꺼냅니다.

raw 문자열 r"..."

정규 표현식에는 \d, \w, \b처럼 역슬래시가 많습니다. 그런데 보통 문자열에서는 Python이 역슬래시를 먼저 해석합니다. "\n"은 줄바꿈 한 글자, "\b"는 백스페이스 한 글자가 됩니다. 문자열 앞에 r을 붙인 raw 문자열은 역슬래시를 그대로 둡니다. 그래서 패턴은 항상 r"..."로 씁니다.

print(len("\n"), len(r"\n"))    # 1 2
print("C:\temp\new")            # \t is a tab, \n a newline: the path breaks
print(r"C:\temp\new")           # C:\temp\new

r을 빠뜨리면 Python 3.14는 SyntaxWarning: "\d" is an invalid escape sequence를 냅니다. 지금은 우연히 동작하지만 앞으로는 오류가 될 예정입니다. first_search의 세 번째 단계에서 이 경고를 직접 볼 수 있습니다.

re 모듈의 함수

찾기: search, match, fullmatch

세 함수는 모두 일치하면 Match 객체를, 일치하지 않으면 None을 돌려줍니다. 차이는 어디서 일치해야 하는가입니다.

import re

s = "주문 010-1234-5678"
print(re.search(r"\d+", s))            # <re.Match object; span=(3, 6), match='010'>
print(re.match(r"\d+", s))             # None: only tries at the start
print(re.fullmatch(r"\d+", "2026"))    # match: the whole string is digits
print(re.fullmatch(r"\d+", "2026년"))  # None

Match 객체에서 group()은 일치한 문자열, start()와 end()는 위치, span()은 그 둘의 튜플입니다. end()는 슬라이스처럼 일치가 끝난 다음 위치입니다.

m = re.search(r"010-\d{4}-\d{4}", text)
print(m.group(), m.start(), m.end())   # 010-1234-5678 4 17

None 확인하기

일치가 없을 때 m.group()을 부르면 AttributeError: 'NoneType' object has no attribute 'group'이 납니다. 정규 표현식에서 가장 자주 만나는 오류입니다. 결과를 쓰기 전에 if m:으로 확인합니다. Match 객체는 참, None은 거짓입니다.

m = re.search(r"\d+", text)
if m:
    print(m.group())
else:
    print("no number")

모두 찾기: findall, finditer

findall은 일치한 문자열을 리스트로, finditer는 Match 객체를 하나씩 돌려줍니다. 위치도 필요하면 finditer를 씁니다.

text = "사과 3개, 배 12개, 귤 7개"
print(re.findall(r"\d+", text))        # ['3', '12', '7']
for m in re.finditer(r"\d+", text):
    print(m.group(), m.span())         # 3 (3, 4)  12 (9, 11)  7 (16, 17)

탐욕적 일치와 비탐욕적 일치

HTML 태그를 찾는 <.+>는 첫 <에서 시작해 .+가 문장 끝까지 간 뒤, >를 찾을 때까지 한 글자씩 되돌아옵니다. 결과는 마지막 >까지의 문장 전체입니다. 수량자 뒤에 ?를 붙이면 비탐욕적이 되어 가장 가까운 >에서 멈춥니다.

$ python3 try_pattern.py '<.+>' '<b>bold</b> and <i>it</i>'
  marked [<b>bold</b> and <i>it</i>]
$ python3 try_pattern.py '<.+?>' '<b>bold</b> and <i>it</i>'
  marked [<b>]bold[</b>] and [<i>]it[</i>]

더 정확한 방법은 "구분자가 아닌 것"을 반복하는 것입니다. <[^>]+>는 >가 아닌 글자만 반복하므로 되돌아갈 일도 없습니다. 로그 분석 패턴의 \[([^\]]+)\]도 같은 방식입니다.

또는(|)과 괄호

|는 우선순위가 가장 낮아서 \bcat|dog\b는 "\bcat 또는 dog\b"가 됩니다. 의도대로 묶으려면 괄호를 씁니다: \b(cat|dog)\b.

그룹과 치환

번호 그룹과 이름 그룹

괄호로 감싼 부분은 따로 꺼낼 수 있습니다. 왼쪽 괄호 순서대로 1, 2, 3번이고, group(0)은 일치 전체입니다. 그룹이 많아지면 번호가 헷갈리므로 (?P<name>...)로 이름을 붙이고 m["name"]으로 꺼냅니다. reformat이 schedule.txt의 날짜와 전화번호를 이렇게 나눕니다.

DATE = re.compile(r"(\d{4})-(\d{2})-(\d{2})")
PHONE = re.compile(r"(?P<head>01[0-9])-(?P<mid>\d{3,4})-(?P<last>\d{4})")

m = DATE.search(text)
print(m.groups())                  # ('2026', '03', '02')
year, month, day = m.groups()

p = PHONE.search(text)
print(p["mid"], p.group("last"))   # 1234 5678
print(p.groupdict())               # {'head': '010', 'mid': '1234', 'last': '5678'}

findall과 그룹

패턴에 그룹이 있으면 findall은 일치 전체가 아니라 그룹을 돌려줍니다. 그룹이 하나면 그 그룹의 문자열, 여러 개면 튜플입니다. 묶기만 하고 잡고 싶지 않으면 (?:...)를 씁니다.

text = "2026-03-02, 2026-04-20"
re.findall(r"\d{4}-\d{2}-\d{2}", text)          # ['2026-03-02', '2026-04-20']
re.findall(r"(\d{4})-(\d{2})-(\d{2})", text)    # [('2026', '03', '02'), ('2026', '04', '20')]
re.findall(r"(\d{4})-(?:\d{2})-(?:\d{2})", text)  # ['2026', '2026']

re.sub: 역참조로 바꾸기

re.sub(패턴, 바꿀 것, 문자열)은 모든 일치를 바꾼 새 문자열을 돌려줍니다. 바꿀 문자열 안의 \1, \2는 그룹이 잡은 글자, \g<name>은 이름 그룹입니다. 바꿀 문자열에도 r을 붙여야 합니다. 빠뜨리면 "\3"이 문자 코드 3이 되어 보이지 않는 글자가 들어갑니다.

print(DATE.sub(r"\3.\2.\1", "2026-03-02 개강"))   # 02.03.2026 개강

date = re.compile(r"(?P<y>\d{4})-(?P<m>\d{2})-(?P<d>\d{2})")
print(date.sub(r"\g<d>/\g<m>/\g<y>", "due 2026-06-15"))   # due 15/06/2026
print(re.subn(r"\d", "#", "PIN 4821, room 301"))  # ('PIN ####, room ###', 7)

re.sub: 함수로 바꾸기

바꿀 것 자리에 함수를 넘기면 일치마다 그 함수가 Match 객체를 받아 불리고, 돌려준 문자열이 그 자리에 들어갑니다. 바꿀 내용이 일치마다 달라질 때 씁니다. 아래 함수는 가운데 자리 수만큼 *를 찍습니다.

def mask(m):
    return m["head"] + "-" + "*" * len(m["mid"]) + "-" + m["last"]

print(PHONE.sub(mask, "담당 김민지 010-1234-5678"))   # 담당 김민지 010-****-5678

re.split과 패턴 안의 역참조

str.split은 구분자 하나만 압니다. re.split은 패턴을 구분자로 씁니다. 패턴 안에 쓰는 \1은 "1번 그룹이 잡은 것과 똑같은 글자"라서, 같은 단어가 두 번 이어진 곳을 찾을 수 있습니다.

re.split(r"\s*[,;/]\s*", "사과, 배;귤  /감 ,  포도")   # ['사과', '배', '귤', '감', '포도']
re.findall(r"\b(\w+) \1\b", "this is is a test test")  # ['is', 'test']

compile과 플래그

re.compile은 패턴을 한 번 해석해 Pattern 객체로 둡니다. re 모듈이 최근 패턴을 캐시하므로 속도 차이는 크지 않지만, 반복해 쓰는 패턴에 PHONE, DATE처럼 이름을 붙이면 코드가 읽기 쉬워집니다. 플래그는 패턴의 해석 방식을 바꾸며, |로 여러 개를 함께 줄 수 있습니다(re.I | re.M).

정규 표현식 검증의 한계

정규 표현식은 모양만 검사합니다. 위 결과에서 볼 수 있는 한계는 다음과 같습니다.

  • 날짜: 월을 01~12, 일을 01~31로 꼼꼼히 제한한 패턴도 2026-02-31을 통과시킵니다. 달마다 다른 날 수와 윤년까지 패턴에 넣으면 아무도 읽을 수 없습니다. 그래서 validate.py는 모양만 정규 표현식으로 보고, 실제로 있는 날인지는 datetime.date(year, month, day)가 ValueError를 내는지로 확인합니다.
  • 이메일: 표준이 허용하는 주소는 매우 다양해서 완전한 정규 표현식은 사실상 쓸 수 없습니다. 실용적인 패턴은 너무 이상한 입력만 거르고, 진짜 검증은 확인 메일을 보내 보는 것입니다. \w가 유니코드라 홍길동@예시.한국도 통과하는데, 이것이 허용할 입력인지는 프로그램이 정할 일입니다.
  • 전화번호: 모양이 맞는다고 실제로 개통된 번호는 아닙니다. -?를 두 번 써서 대시가 하나만 있는 010-12345678도 통과합니다. 허용 범위를 넓힐수록 이런 경우가 늘어납니다.

모양은 정규 표현식으로, 의미는 코드로 검사한다는 원칙을 기억해 둡니다.

MULTILINE과 셸의 grep

파일 전체를 한 문자열로 읽으면 ^는 문자열 맨 앞 한 곳에서만 일치합니다. re.MULTILINE을 주어야 줄마다 일치합니다.

셸의 grep도 정규 표현식을 씁니다. grep -E '" [45][0-9]{2} ' access.log는 오류 줄을 바로 보여 줍니다. 다만 grep -E의 문법(확장 정규 표현식)에는 \d가 없어서 [0-9]로 씁니다. 빠르게 훑을 때는 grep, 세고 표를 만들 때는 Python이 편합니다.

유니코드 범위 [가-힣]

완성형 한글 11,172자는 유니코드에서 U+AC00(가)부터 U+D7A3(힣)까지 빈틈없이 이어져 있습니다. 그래서 [가-힣] 하나로 모든 완성된 한글 글자를 가리킬 수 있습니다. ㅋ, ㅠ 같은 낱자(호환용 자모)는 다른 구역(U+3131~U+3163)이라 [ㄱ-ㅎㅏ-ㅣ]로 따로 적습니다.

print(hex(ord("가")), hex(ord("힣")))          # 0xac00 0xd7a3
re.findall(r"[가-힣]", "한글 ㅎㅏㄴ 漢字 abc")       # ['한', '글']
re.findall(r"[ㄱ-ㅎㅏ-ㅣ]", "한글 ㅎㅏㄴ 漢字 abc")   # ['ㅎ', 'ㅏ', 'ㄴ']

hangul은 상품 후기에서 한글 단어, 자모(ㅋㅋㅋ, ㅠㅠ), 영어 단어, 별점을 각각 골라내고, 기호와 자모를 지운 깨끗한 문장을 만듭니다.

\w는 유니코드다

Python 3에서 문자열 패턴의 \w, \d, \b는 유니코드 기준입니다. 한글도, ï 같은 악센트 글자도 단어 글자입니다. 영문과 숫자만 원하면 re.ASCII를 주거나 [A-Za-z0-9_]로 직접 적습니다.

한계: 조사는 모양으로 알 수 없다

"배송이"와 "배송은"을 같은 단어로 세고 싶어 끝의 조사를 떼는 패턴을 만들어 볼 수 있습니다. 배송이, 품질은, 포장도, 고기를은 잘 되지만 "나이"는 "나"로 잘립니다. 끝 글자 "이"가 조사인지 단어의 일부인지는 모양만으로 알 수 없기 때문입니다. 한국어 단어 분석은 사전을 가진 형태소 분석기의 일이고, 정규 표현식은 그 전 단계의 정리(기호 지우기, 숫자·자모 골라내기)에 씁니다.

josa = re.compile(r"([가-힣]+?)(은|는|이|가|을|를|도)?")
for w in ["배송이", "품질은", "포장도", "고기를", "나이"]:
    print(w, "->", josa.fullmatch(w)[1])   # 배송 품질 포장 고기 나(!)

자주 하는 실수

  • r을 빠뜨린다. "\b"는 단어 경계가 아니라 백스페이스 글자입니다. 패턴과 바꿀 문자열 모두 r"..."로 씁니다.
  • None을 확인하지 않는다. re.search(...).group()을 바로 이어 쓰면 일치가 없을 때 AttributeError가 납니다.
  • 검증에 search나 match를 쓴다. 입력 전체를 검사하려면 fullmatch입니다.
  • 점을 이스케이프하지 않는다. .은 아무 글자입니다. 진짜 마침표는 \., 대괄호 안에서는 [.]도 됩니다.
  • 탐욕적 .*에 놀란다. .*?나 [^구분자]*를 씁니다.
  • findall이 그룹을 돌려준다는 것을 잊는다. 묶기만 하려면 (?:...)입니다.
  • 정규 표현식으로 모든 것을 하려 한다. 날짜가 실제로 있는지, 이메일이 실제로 가는지는 코드와 다른 수단으로 확인합니다. HTML이나 JSON처럼 중첩된 구조는 전용 파서(html.parser, json)를 씁니다.

  • 그룹으로 일치의 일부를 꺼내고, 역참조와 함수로 바꿉니다.
  • 자주 쓰는 패턴은 re.compile로 이름을 붙이고, 길면 re.VERBOSE로 주석을 답니다.
